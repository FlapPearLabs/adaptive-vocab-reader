# V0.1：1,000 词本地词汇阅读垂直切片实施规格

日期：2026-07-22
状态：本地 `/to-spec` 已完成；本规格综合已确认产品规则、算法规格与可丢弃原型，不引入新的待确认产品决策；它不授权实现、提交、远端写入、发布或部署。

权威产品规则仍是 [`RULES.md`](../RULES.md)。领域语言见 [`CONTEXT.md`](../CONTEXT.md)，单词级与词典优先的架构决定见 [ADR-0003](../docs/adr/0003-词典优先的单词级-v0.1.md)。如有冲突，以用户最新指示和 `RULES.md` 为准。

## Problem Statement

用户需要在正常 HTTPS 英文网页阅读时，及时得到自己真正不会的词的简短中文帮助，而不想看到整页翻译、等待模型生成，或先经历一套词典清洗工程。

当前没有可安装的扩展、词典构建产物或用户状态存储。若直接从完整一万词、义项、模型、长期学习计划或多数据源开始，会重新引入已经明确排除的复杂度。垂直切片必须先证明以下闭环在真实 Chrome 页面可用：

```text
1,000 个确定性本地词条
→ 正文命中与内存查询
→ 强提示 / 轻提示 / 不提示
→ 会／不会直接反馈与初测
→ 刷新后本地保留
```

它还必须证明“提示逐步贴近用户”不是只凭一个总分：显式状态优先，未知词才使用十频段 Beta/PAV 画像，并通过边界校准和隐藏词审计保守地决定是否静默。

## Solution

交付一个仅供单用户本地 dogfood 的 Chrome Manifest V3 扩展垂直切片。它内置从固定 ECDICT 快照确定性筛选出的 1,000 个合格主词条，且不依赖网络、LLM、Ollama、DeepSeek、Kaikki 或 Service Worker 词典查询。

内容脚本在普通 HTTPS 页面正文中查本地词典、调用“词汇展示与测试策略”深模块获得展示决策，并只对需要帮助的命中词做最小 DOM 标注。扩展的本地画像协调器负责状态持久化和跨标签同步，但不参与每个单词的词典查询。用户可从扩展弹窗开始首次 50 题测试和每日校准轮，并在页面上立即标记会／不会。

这不是“背单词插件”：每日 5–30 题只校准词汇范围、核验活跃生词状态和审计不提示边界；它没有到期复习、间隔、遗忘曲线或学习计划。

### 最高测试 seam（已确认）

本功能的最高确定性测试 seam 是 **词汇展示与测试策略模块**。给定固定的词典快照、用户画像、词汇状态、审计记录、轮次和页面命中词，它只输出：

1. 每个命中词的强提示、轻提示或不提示决策；
2. 首测或每日校准轮的冻结题目计划；
3. 用户作答或手动标记后的原子状态变更。

页面扫描、弹窗 UI、Service Worker 和存储适配器都只能消费这些输出，不能各自重算后验、阈值、抽样顺序或审计清理。这一 seam 沿用现有算法规格和原型的测试边界；浏览器端到端测试则验证这条 seam 的结果确实呈现在页面与刷新后的状态中。它是后续 tickets 的共同验收边界。

## User Stories

1. 作为单用户 dogfood 读者，我想安装一个仅本地工作的 Chrome 扩展，以便不依赖账号、网络或模型服务即可阅读英文网页。
2. 作为读者，我想在普通 HTTPS 英文正文中看到词典命中词，以便插件不会要求我复制粘贴内容到翻译工具。
3. 作为读者，我想让词典查询在当前标签页内存中完成，以便鼠标悬停和页面阅读没有可感知的后台或网络等待。
4. 作为读者，我想让不会词在同页第一次出现时显示下划线和简短中文，以便能立即继续阅读。
5. 作为读者，我想让同页重复出现的不会词只保留可悬停的下划线，以便行内中文不会反复打断阅读。
6. 作为读者，我想让已确认会的词不提示，以便页面不会被我已经掌握的词覆盖。
7. 作为读者，我想让未知词默认轻提示，只有画像和独立审计都满足保守门槛时才不提示，以便避免把生词静默隐藏。
8. 作为读者，我想在命中词上立即标记会或不会，以便当前页面的提示和活跃生词表同步改变。
9. 作为读者，我想让普通浏览、悬停、查看释义和滚动不影响掌握状态，以便系统不会把“看见过”误判为会。
10. 作为读者，我想完成覆盖十个词频段的固定 50 题首测，以便插件建立初始画像而不是凭总分武断隐藏词。
11. 作为读者，我想在首测时选择不确定，以便猜不出来的词被保守地视作不会。
12. 作为读者，我想让首测答对词立即不提示、但可能被随机核验，以便偶然猜对不会永久造成漏提示。
13. 作为读者，我想自选每日 5–30 题校准轮，以便系统逐步了解我的词汇范围，而不是强迫我完成背词任务。
14. 作为读者，我想让每日校准轮中的活跃生词核验只改变该词，以便网页手动标记和复测偏差不会污染总体画像。
15. 作为读者，我想让边界校准和隐藏词审计更新画像，并在候选不足时按照受控回填规则出题，以便题量与误差边界都有可解释行为。
16. 作为读者，我想刷新或重新打开网页后仍保留词汇状态、初测进度和画像，以便不必重复标记或重新测试。
17. 作为读者，我想让插件跳过导航、代码、表单、评论和扩展自身节点，以便不干扰网站功能或无关文本。
18. 作为读者，我想确认插件不保存 URL、域名、页面标题、网页正文、句子或浏览历史，以便阅读数据不变成隐形追踪记录。

## Implementation Decisions

### 1. 运行时分层

V0.1 使用 Chrome Manifest V3。内容脚本是页面 DOM 与词典热路径的唯一执行位置：它读取和最小化修改 DOM，并在独立执行环境中维护当前标签页的只读词典索引。Chrome 官方文档说明内容脚本可直接操作页面 DOM、处于隔离世界，且能直接使用 `chrome.storage` 与 `runtime` 的必要接口；这正适合页面标注，但不意味着将词典查询转发到后台。 [Chrome 内容脚本文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)

Service Worker 只担当本地画像协调器：接收测试与页面手动动作、加载或写回画像快照、向标签页广播已确认的状态变更。它不得加载完整词典、不得参与单词悬停或批量查词。Chrome 的 Service Worker 会按事件加载并在空闲时卸载，因此不能作为词典热路径的内存宿主。 [Chrome Service Worker 文档](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers)

页面、弹窗与 Service Worker 均须通过小而稳定的模块 Interface 协作；不得让 UI、DOM 适配器或持久化适配器知道 Beta 后验、PAV 或 Wilson 公式。

### 2. 词汇展示与测试策略模块

该深模块是唯一的领域决策模块。它接收规范化单词、十频段词典元数据、已冻结的用户画像、单词状态、审计记录、安装随机种子和轮次；它返回展示决策、冻结题目与原子状态变更。

模块必须完整实现当前已确认策略：

- 三种状态：会、不会、未知；状态优先于预测，词形命中不传播状态。
- 会不提示；不会同页首次强提示、重复可悬停；未知默认轻提示。
- 高置信不提示同时要求未知、后验均值 `≥ 0.85`、单侧 90% 下界 `≥ 0.70`、至少 20 道随机隐藏词审计、以及漏提示率 Wilson 单侧 90% 上界 `≤ 30%`。
- 首测为十频段各五题；每题四个中文释义选项加“不确定”。正确选项与干扰项在开始时冻结。
- 十频段使用 `Beta(1,1)` 先验；PAV 合并 `m` 段时使用 `Beta(m + ΣC, m + ΣU)`。
- 每日 `N=5..30` 的目标配额为 `floor(N/5) / ceil(2N/5) / 剩余`；候选不足仅在边界校准与隐藏词审计之间确定性交替回填，二者也耗尽才少出题。

现有 Python 原型只作为此策略的行为证据，不能直接提升或复制为生产模块。

### 3. 词典构建与运行时只读核心包

构建模块接收用户以后明确授权取得的固定 ECDICT CSV 快照与目标条数，输出两个只读产物和一个构建报告：

- **核心词典**：规范化主词条到音标、词性和短中文释义的紧凑映射；十频段编号位于独立的频段表，避免给运行时词典条目增加无关字段。垂直切片目标是 1,000 条，正式扩展才按同一规则扩至约 10,000 条。
- **词形映射**：仅由 `exchange` 导出的词形到已入包主词条映射；无目标主词条的映射必须丢弃。
- **构建报告**：输入版本、获取日期、输入哈希、筛选规则、条数、缺字段和异常淘汰原因、产物哈希与许可证声明。

筛选规则严格采用已确认的 `frq` 正序主排、`bnc` 缺失补位、`tag` 不参与默认排序；没有音标、中文释义、频率排名或存在明显异常的候选必须淘汰递补。词性优先读取 `pos`；该列为空时，只能从 `translation` 每行开头已有的 `n.`、`vt.`、`adj.` 等显式前缀机械提取，仍无词性则淘汰。不得调用任何模型或人工逐条补全。`exchange` 只接受实际屈折代码，关系代码不能生成词形。ECDICT 提供这些字段与 `exchange`，但不提供官方“一万高频词”成品表，因此项目的输入和排序必须可复现。见 [ECDICT 核验](../work/research/2026-07-22-ecdict-高频核心包可行性核验.md)。

内容脚本在每个标签页首次需要处理页面时一次加载本地核心包到内存，后续用规范化单词或词形映射直接查询。静态词典不得放入 `chrome.storage`、IndexedDB、Service Worker、网络 API 或模型调用链。

### 4. 页面扫描、标注与交互适配器

页面适配器只将正文 Text Node 转换为候选 token，并对策略模块返回的强提示或轻提示执行最小 DOM 标注。它必须：

- 跳过 `script`、`style`、`noscript`、`code`、`pre`、表单控件、导航、评论和扩展自身节点；
- 不改变宿主页面的文本顺序，不插入 `<br>`、独立翻译块或固定翻译栏；
- 用事件委托和单一悬浮释义视图处理交互，不能给每个词注册独立事件处理器；
- 对同一页面动态插入的正文增量处理，避免因 MutationObserver 重复扫描已处理节点；
- 在当前页面状态变更后，只更新受影响的命中词，而不是全页重新扫描。

页面提示密度不在本切片设置“每 250 词”或其他固定配额。现有研究不支持这种跨页面常数；布局拥挤问题留待基础闭环通过后独立 PoC。见 [页面提示密度与滚动研究](../work/research/2026-07-17-reading-context-window-research.md)。

### 5. 本地画像与持久化

用户状态、画像、审计与安装随机种子保存在扩展专用的 `chrome.storage.local`，并以单一版本化画像快照读写。该 API 支持异步批量读写；本地存储默认上限为 10 MB，足以覆盖 1,000 词切片的最小状态，不申请云同步或无限存储权限。 [Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)

持久化快照至少包含：schema 版本、词典产物版本、安装随机种子、首测状态、测试轮次、每词会／不会／未知状态及来源、活跃生词表、十频段证据、审计统计、待审计标记和最近冻结的测试计划。不得包含 URL、域名、页面标题、正文、句子、页面 token、浏览历史或模型输出。

Service Worker 初始化时必须将 `storage.local` 设为仅扩展可信上下文可访问；内容脚本只通过 `runtime` 消息取得当前页面所需的画像快照，不直接读取原始持久化数据。内容脚本只缓存当前已加载的画像快照；Service Worker 是写入协调器。一个动作先经策略模块生成原子变更，再由协调器合并、持久化并广播新快照。若扩展重启，协调器必须在处理动作前从 `chrome.storage.local` 异步加载快照；不能假定 Service Worker 全局变量常驻。

### 6. 首测、每日校准与选项生成

扩展弹窗是 V0.1 启动首测与自愿每日校准轮的唯一入口；页面阅读不应被强制弹题。弹窗读取当前画像，向策略模块索取已冻结题目计划，并在用户作答后提交原子状态变更。

每题的四个中文选项必须来自同一固定词典快照：一个为正确短中文，三个为其他不同主词条的短中文；所有选项需去重且由安装种子、题目和题库版本确定性排列。无法生成四个不同短中文选项的条目不得进入测试候选池，且构建报告必须计数。`不确定` 始终独立于四个中文选项。

首次 50 题、每日候选桶、审计来源、展示决策和预测版本都必须在作答前冻结。答题后不得用更新过的画像重算该题的展示或漏提示归类。

### 7. 实施依赖顺序

后续 ticket 必须按以下阻塞顺序拆分：

1. **基础工程与词典构建**：创建最小 MV3 构建骨架；以本地 fixture 验证 1,000 词确定性包、词形表与报告。不得下载真实 ECDICT，除非另获授权。
2. **领域策略模块**：以当前原型的外部行为为准，TDD 落实状态、画像、首测、校准、审计与展示决策。
3. **本地画像协调器**：版本化快照、`chrome.storage.local`、Service Worker 重启加载和跨标签变更通知。
4. **网页阅读适配器**：内容脚本词典内存加载、正文增量扫描、三档标注、事件委托和手动会／不会。
5. **弹窗测试适配器**：首测、每日校准、冻结选项和不确定动作。
6. **真实浏览器闭环验收**：加载未打包扩展，执行静态正文、动态插入、长文和刷新持久化场景。

任何后续 ticket 均不得将模型、词典扩展、义项、MWE、云同步或密度实验作为前置依赖。

## Testing Decisions

### 测试原则

测试只断言跨策略模块 Interface 的可见结果、持久化后的状态，以及真实页面的行为；不测试 Beta CDF、PAV 堆栈、DOM 工具或 `chrome.storage` 调用次数等内部实现细节。策略模块应有最密集的确定性单元测试；浏览器场景用于验证调用方没有绕过该 seam。

### 策略模块验收

1. 固定输入、安装种子和轮次得到相同首测、每日计划、干扰项顺序和审计来源。
2. 十频段初测严格各五题；答对、答错与不确定的状态、活跃生词表与审计标记符合规则。
3. 页面手动会／不会立即改变单词状态和展示，却不更新频段画像。
4. 普通曝光、悬停、查看释义和滚动不改变任何状态或画像。
5. `n=19` 审计永远不静默；`n=20,k=3` Wilson 上界允许、`n=20,k=4` 不允许高置信不提示。
6. PAV 违反时正确合并；合并 `m` 段后 Beta 均值与 PAV 加权均值相等。
7. 每日 `N=5`、`10`、`30` 在候选充足时满足 `1/2/2`、`2/4/4`、`6/12/12`；候选不足仅按受控回填规则补足。
8. 初测单次答对与高置信未知词的审计候选交替；审计答对清理标记，审计失败立即进入不会与活跃生词表。

### 数据构建验收

1. 同一 ECDICT 输入与规则产生相同核心包、词形表、报告和内容哈希。
2. 缺音标、词性、中文释义、无效词形目标和异常记录被明确计数并淘汰。
3. fixture 覆盖普通主词条、常见屈折命中、短语淘汰和四选项无法去重的测试候选淘汰。
4. 垂直切片只验证约 1,000 条；达到该闭环后，使用相同构建模块才允许扩到约 10,000 条。

### 浏览器闭环验收

在加载的未打包扩展中，用静态正文、SPA 动态插入和无限滚动 fixture 验证：

1. 正文词命中后展示强／轻／不提示，且代码、导航、表单、评论与扩展节点不被扫描。
2. 同页第一次不会词有行内短中文；重复出现只保留下划线与共享悬浮释义。
3. 页面标记会／不会立即更新当前显示；刷新后保留；多个标签页最终收敛到同一状态快照。
4. 首测和每日校准可从弹窗发起，作答后的状态变化在已打开页面生效。
5. 验收记录长文扫描耗时、单批主线程耗时、DOM 增量与布局影响；当前不预设性能数值，先记录真实基线。
6. 存储导出或开发检查中不含 URL、域名、页面标题、正文、句子或浏览历史。

## Out of Scope

- 一万词扩容、公开上架、商用或云同步；ECDICT 逐条公开再分发权利链确认前只能个人 dogfood。
- Kaikki、OEWN、COW、多源词典、PDF/OCR 提取、人工或 LLM 词典清洗。
- Ollama、LM Studio、DeepSeek、任何云模型、自动或手动上下文解释、全文翻译、模型缓存。
