# 浏览器词汇学习插件 V0.1 产品规格

状态：产品级决策已由可用等价 Grill 流程收口；`/grill-with-docs` 未安装，未被伪造为已执行。下一步先做词典映射／清洗 PoC，再重新 `/to-spec`；本文件尚不是最终产物，也尚未授权实现。

真相来源：[RULES.md](../RULES.md)、[CONTEXT.md](../CONTEXT.md) 与用户已确认的讨论。

范围：单用户、本地优先、Chrome 可加载 dogfood 扩展；不创建 Issue、不发布、不进入 Chrome 商店流程。

## Problem Statement

目标用户大致具有高考英语 110 分或 CET-4 水平：能够阅读大多数常见英文，却会被偶发的生词、短语、俚语或特殊义项打断。普通整页翻译会掩盖原文并让阅读依赖翻译；按固定等级高亮又不了解用户实际会什么。

用户需要一个阅读脚手架：只在真正可能造成卡顿的表达处提供极短中文帮助，允许立刻纠错，并随着测评、浏览反馈和复测逐渐收敛到其个人薄弱点。系统必须区分表达义项、MWE 与词形，不能把认识 `run` 错当为认识 `run into` 或所有派生词。

## Solution

扩展在普通 HTTPS 英文网页正文中识别候选表达，依据个人词汇模型和本地词典决定是否提示。首次提示以同一行内的“下划线＋简短中文”显示，例如 `cat（猫）`；它不是英文下方的翻译块，也不主动插入换行。重复出现只保留下划线。用户可对误提示标记“我会了”，或左键选中漏标单词/词组并标记“不会”。这两类反馈立刻改变当前页，并进入可审计证据系统；详细记录按已确认的保留、压缩和核心保护规则处理，并非所有原始事件永久保存。

词典为主路径，本地模型为可选后备。所有学习数据保留在本机；扩展只向 loopback 地址上的 Ollama/LM Studio 发送单个表达的最小充分语境，不向非 loopback 地址上传网页或学习数据。

```text
固定 50 项初测 / 阅读反馈 / 主动复测
              ↓
个人表达义项状态与证据账本
              ↓
正文增量 → 表达候选 → 词典与语境判断 → 成本敏感显示
              ↓
行内中文、下划线、我会了 / 不会 / 上下文解释
              ↓
本地持久化、回顾、保温抽检与持续校准
```

显示决策必须遵循完整级联：高召回表达候选 → MWE/粗义项与语境可信度 → 个人未知概率 → 成本敏感的行内提示/轻提示/隐藏/拒答 → 证据更新与保温抽检。校准不足时偏向高召回，但低语义置信不能强行输出确定中文。

## User Stories

1. 作为有一定英语基础的中文读者，我接受首次一次完成固定 50 个校准词汇／表达，再进入阅读，以获得更可靠的初始画像。
2. 作为读者，我希望初测结束后直接进入阅读，而不是在浏览时被未完成的初测题分批打断。
3. 作为读者，我希望能主动重新测评，以更新我当前的词汇范围。
4. 作为读者，我希望系统根据我的实际反馈提示可能不会的表达，而不是按 CEFR 或文章难度机械翻译。
5. 作为读者，我希望首次遇到一个需要帮助的表达时看到下划线和简短行内中文，以免打断阅读。
6. 作为读者，我希望同页重复遇到同一表达时只看到下划线，以保持页面简洁。
7. 作为读者，我希望长文章进入新章节时可再次看到一次行内中文，以免忘记刚才的释义。
8. 作为读者，我希望点击或选中误提示表达并标记“我会了”后，当前页面中高置信识别为同一表达义项的提示立即消失，未来默认不再显示，同时不误隐藏不同义项、MWE、派生词或身份不确定的实例。
9. 作为读者，我希望圈选系统漏掉的单词或词组并标记“不会”后，立即看到当前语境释义，并让它进入后续学习。
10. 作为读者，我希望 `running`、`runner`、`rerun`、`run into` 和 `run` 的不同义项被谨慎区分，而不是被一个“会 run”简单隐藏。
11. 作为读者，我希望普通阅读不会弹出强制答题窗口，回顾可以跳过或调整。
12. 作为读者，我希望已标记为会的表达偶尔被低频抽检，答错后自动重新激活，而不是永久消失。
13. 作为读者，我希望系统在语境不足时明确展示不确定性或提供候选，而不是塞给我貌似确定的错误中文。
14. 作为读者，我希望可选择配置 Ollama 或 LM Studio，在本机获得缺词、俚语和语境义项的解释。
15. 作为读者，我希望未配置或关闭本地模型时，词典、阅读和反馈闭环仍然正常工作。
16. 作为读者，我希望知道本地模型实际会收到什么文本，并确信它不会读取整页、普通浏览历史或云端数据。
17. 作为读者，我希望在“数据与隐私”页审计学习状态、证据、缓存、词典版本、数据体积和本地模型请求字段。
18. 作为读者，我希望生词本只保留尚未确认掌握的表达：初测确认薄弱、我标记“不会”或复测／回顾失败的项；不显示“正在学习”等阶段状态。只有我明确“我会了”或在新语境直接复测正确后才移出，系统猜测、普通曝光或查释义不应自动改变词本。
19. 作为读者，我希望按英文表达或中文短释义搜索生词本，在单条上确认“我会了并移出”且可撤销，并一次性导出 CSV。
20. 作为读者，我希望导出可阅读的生词本 CSV，并导出可恢复的完整个人资料 JSON。
21. 作为读者，我希望“清空缓存”不会误删学习状态，而“重置全部学习数据”必须二次确认。
22. 作为读者，我希望 SPA 和无限滚动新增的正文也被处理，同时代码、导航、表单和评论不受影响。

## Implementation Decisions

### 核心 Module 与测试 seam

本轮规划提出以**阅读辅助协调器**作为 V0.1 的高层 seam，待重新 `/to-spec` 时正式接受或修订。其 Interface 接收“规范化正文增量、当前个人状态和用户动作”，输出“应渲染的标注、状态变更、复习候选和可选本地模型任务”。它封装候选表达、个人模型、词典、语境、缓存和提示预算的复杂性。该提案记录在 [ADR-0001](../docs/adr/0001-reading-assistance-coordinator.md) 中，不等同于用户产品行为规则。

浏览器 DOM、静态词典、本地持久化、Ollama 与 LM Studio 都通过 Adapter 提供给该 Module；调用方不需要理解词形归一、MWE、义项降级、缓存合并或模型队列。这样同一 Interface 可被正文 fixture、SPA fixture、真实 content script 和后续 PDF/字幕文本适配器使用。

需要的 Adapter 包括：

- 文本来源 Adapter：交付规范化正文块、章节边界和增量，不把页面 DOM 细节泄漏给核心。
- 词典 Adapter：按表达和语境线索返回网页提示最小记录（`expression / pos / short_zh`）或“无可靠中文”；来源与义项追溯只通过独立构建审计路径查询，不混入用户提示载荷。
- 本地模型 Adapter：将结构化最小充分语境提交给 Ollama 或 LM Studio，并返回已校验的短解释。
- 本地存储 Adapter：读写当前可信状态、重要证据、代表语境、缓存和审计元数据。
- 渲染 Adapter：将协调器给出的标注绑定回原文，并处理即时删除、异步更新和页面失效。

### 表达、语境与个性化

- 建模单位是**表达义项**，不是整个 lemma 或词族。词典/MWE 关系图只用于候选、特征、来源和审计，不直接传播掌握真值。该取舍记录在 [ADR-0002](../docs/adr/0002-expression-sense-and-evidence-graph.md)。
- 屈折形式可以共享规范化证据的边界、透明派生的软迁移、粗义项粒度和 MWE 规则将在实现前的原型/Spec 补充中校准；不得凭规则直接把派生词标为会。
- 初始测评使用词频、CEFR 等作为先验，首次一次完成固定 50 个校准词汇／表达后才允许开始阅读；初测不采用渐进式追加或提前停止。此后用户可主动重新测评以更新先验。
- 校准不足时采用偏高召回的保守提示策略；稳定后再逐步收敛提示，不能靠粗暴隐藏制造“变聪明”的假象。
- 系统未知表达识别的长期目标是：在独立本地语境审计集中，用户随后明确为“不懂且影响理解”的表达义项实例里，95% 以上已在标签出现前被系统识别并提供至少轻提示；该指标不以主动补标、普通曝光或已知词准确率替代。
- 用户学习效果的长期目标是：个人目标词汇集合（初测薄弱项、标记“不会”的项、复测失败项和回顾项）中，95% 以上在新语境复测中得到正确的明确确认；普通曝光、查看释义或点击不计为掌握。
- 用户主动给出的“我会/不会”是强直接证据，优先于个性化模型、表达关系、词频和 CEFR 先验。同一表达义项以最新明确用户动作优先；撤销指定动作后恢复此前有效状态。一般测评只更新整体能力与类别先验，只有明确、直接测试同一表达义项的较新复测作答才能覆盖旧反馈。查看释义记录为独立行为信号，其权重和是否改变状态待校准；普通曝光不是掌握证据。
- 已会表达通过保温抽检复核。保温抽检频率、降级和证据优先级将在 dogfood 数据出现后校准。
- 回顾可跳过、关闭和调整；当前产品方向是每天约 2 分钟、每次约 5–10 个高信息价值表达，精确频率通过 dogfood 微调。
- 系统须分别判断“表达是否成立”“当前义项是什么”“用户是否理解”“是否值得打断”，不能把这些问题合成一个词频阈值。

### 页面交互与渲染

- 只处理普通 HTTPS 英文网页正文，包括新闻、博客、Wikipedia、技术文档及 SPA/无限滚动新增正文。
- 排除代码、导航、表单、评论和扩展自身节点。V0.1 不支持 PDF、字幕、电子书、OCR、跨域 iframe 和浏览器内置页。
- 当前页面中一个表达首次以“下划线＋同一行内中文”显示，例如 `cat（猫）`；不得注入 `<br>`、独立翻译容器或主动换行。后续只保留下划线，悬停或点击查看；新章节可再次显示一次行内中文。
- 用户标记“我会了”必须立刻移除当前选中处及当前页面中高置信识别为同一表达义项的提示，未来页面默认不再提示；不同义项、MWE、派生词和身份不确定的实例不得因此隐藏。用户标记“不会”必须立刻显示当前语境提示并加入后续闭环。
- 网页 CSS 必须与注入标注隔离；异步解释必须带页面/目标版本标识，防止页面切换或节点移除后回写旧位置。
- 强提示预算按当前可见及近可见正文的实际行内负担动态控制，而非按全文累计词数或固定 250 词窗口；段落/可靠章节只负责首次/重复/重获提示机会的语义去重。局部过于拥挤时，普通候选降为下划线加悬停/点击查看，用户明确“不会”的表达始终即时显示。强提示密度、相邻聚集、近可见缓冲与宿主页面实际拥挤度是待 dogfood 校准的控制量；固定词数（包括 250）仅作为对照条件，不能成为默认规则。
- 研究依据、局限与同一用户内的三条件 dogfood 设计见 [阅读上下文窗口研究](../work/research/2026-07-17-reading-context-window-research.md)。

### 词典数据与释义

- 默认核心包从固定快照的 Kaikki/Wiktextract 英语数据构建；构建审计层保留 lemma、词性、词形、义项、已有简中短释义及上游指针。首版运行时网页提示记录只包含 `expression`（单词或 MWE）、简化 `pos` 和当前粗义项的 `short_zh`；网页本身提供例句，不把发音、词源、考试／CEFR、领域、学习阶段、难度或精确词频塞入本轮提示数据。
- 来源／义项指针、输入与产物哈希、接受／拒绝与丢弃原因、Schema／Skill／模型版本、运行和成本信息独立存入构建审计外壳；它们不属于用户提示字段。模型输出只能作为待审候选，不得把无上游依据的扩写、例句或新义项提升为词典事实。
- Wiktionary/Kaikki 衍生包独立版本化，并保留上游署名、适用许可证和本项目变更说明；多数据源组合发布前继续做正式许可审计。
- OEWN 用于英文词形与义项骨架；COW 用于构建期义项一致性校验；二者不直接渲染为页面中文。
- 核心包随扩展提供；长尾包仅在用户主动选择后本机安装。ECDICT 不作为默认发布数据，最多作为清晰标记的第三方导入或对照。
- 每个词典包必须带版本清单，含上游、版本、许可证、内容哈希和构建版本；构建过程必须可重复并产出覆盖、冲突、重复、丢弃原因和许可报告。
- 词典缺少可靠中文或当前义项冲突时，应给英文 gloss、轻提示或“本地模型解释”，不能把模型文字伪装为词典事实。

### 本地模型

- 本地模型可选，支持 Ollama 和 LM Studio；核心阅读不依赖它，也不提供整页翻译。
- 仅允许 `localhost`、`127.0.0.1` 与 `[::1]`。V0.1 禁止云 Provider。

```text
正文 DOM → TextSource/协调器 → 本地词典即时释义
                              ↓ 仅在缺词或义项冲突时
扩展后台 Service Worker → loopback Provider → 短 JSON 校验
                              ↓
页面/目标版本校验 → Renderer 只更新绑定表达
```

- 默认最小充分语境为目标表达与所在完整句；仅在指代、省略、引语续接、强义项冲突或用户主动要求上下文解释时，才追加相邻句，最多前后各一句。
- 请求体不得包含 URL、页面标题、完整段落、完整网页或普通浏览历史，只允许目标表达、允许范围内的句子、候选义项和必要本地配置。
- 用户手动标记“不会”后，如词典缺词或义项冲突，自动调用已启用的本地模型。系统已决定显示的未知表达也只在同样条件下后台补全；普通可靠词典命中不调用模型。
- 自动补全可关闭。当前用户动作优先，后台请求串行、去重、可取消；页面离开时结果作废。
- 模型结果只更新与请求绑定且版本仍匹配的目标表达，不触发整页重新扫描或翻译。
- 模型未启动、超时或返回无效结构时，立即退回词典或轻提示，不阻塞阅读；词典也无可靠内容时明确显示“词典暂缺／需要更多上下文”，不编造释义。结果标为“本地模型解释”。

### 本地数据、审计与容量

- 运行时学习数据保存在 Chrome 扩展 IndexedDB；模型设置也只能保存在本机并接受审计，具体采用 `chrome.storage.local`、IndexedDB 或等价封装在技术栈冻结时决定。Chrome 管理物理目录，产品只承诺可见的逻辑位置和审计能力。
- 长期数据分为受保护核心数据与可淘汰数据。核心是当前可信状态与最小证据摘要，不因容量整理自动删除；可淘汰数据包括详细证据记录、代表语境和释义缓存。
- 每个表达＋粗义项最多保留 3 条代表语境和 12 条近期重要证据。旧详情压缩为证据摘要。
- 可淘汰数据预算为 64 MB，不包含静态词典和受保护核心；48 MB 启动主动压缩和低价值淘汰；64 MB 停止新增可淘汰缓存并优先淘汰低价值数据。整理在浏览器空闲时增量执行，不阻塞阅读。
- 每次写入可淘汰数据时立即去重、合并并失效旧缓存；不得等到容量压力才处理陈旧或重复内容。
- 合并冲突时，用户明确反馈及同一表达义项的直接复测结果不被缓存、词典或模型覆盖；其他内容先按当前义项正确性与来源可靠性选择，正确性相同才选更新版本，含义与可靠性等价才选更短文本。
- 受保护核心接近异常体积时提醒用户导出或主动清理，但不得为满足 64 MB 预算而静默删除。
- 不保存完整网页正文、普通浏览历史或来源追溯元数据（URL、页面标题、域名、路径等）；仅长期保存与明确反馈或复测有关的最小充分语境。V0.1 优先交付可用生词本、CSV 导出和可恢复备份。
- 生词本是“尚未确认掌握”的待确认清单：初测确认薄弱、用户标记“不会”或复测／回顾失败时进入；“不会”立即入本。只有用户明确“我会了”，或同一表达义项在新语境直接复测正确确认时才移出。系统预测、普通曝光或查看释义都不自动改变词本。词本不维护“正在学习”等阶段状态。
- 生词本仅提供按英文表达或中文短释义搜索、单条“我会了并移出”（可撤销）和一次性 CSV 导出；不提供学习阶段标签、来源追溯、上下文查看或复杂分类。
- “数据与隐私”页显示数据类别、数量、大小、保留理由、词典版本和模型发送字段，但不展示或搜索代表语境／单条证据。`vocabulary.csv` 仅导出当前词本，至少含表达、短释义和复习信息；已移出词条不在其中。`profile.json` 用于可恢复的完整本地备份。
- 清空可淘汰缓存和重置全部学习数据必须独立；完全重置二次确认。

## Acceptance Criteria

| ID | 必须满足的可观察结果 |
| --- | --- |
| AC-01 | 首次使用必须一次完成固定 50 个校准词汇／表达后才可进入阅读；初测不得渐进式分批或提前停止。 |
| AC-02 | 初测完成后直接进入阅读；后续只有用户主动发起的重新测评可以更新先验，不得把初测遗留题强制插入阅读。 |
| AC-03 | 同页首次未知表达显示下划线和行内中文，后续仅下划线；新章节可再次显示一次。 |
| AC-04 | 标记“我会了”后，当前选中处及当前页面中高置信识别为同一表达义项的提示立即消失，未来页面默认隐藏；不同义项、MWE、派生词和身份不确定的实例不被隐藏。 |
| AC-05 | 圈选单词/词组并标记“不会”后立即进入显示、个人状态和复习闭环；无可靠中文时明确降级。 |
| AC-06 | 任意次数普通曝光都不能直接晋级为掌握。 |
| AC-07 | `run` 的状态不能自动隐藏 `run into`、`rerun` 或不同义项；屈折/派生的正向共享必须通过 PoC 证明。 |
| AC-08 | 语境或词典不可靠时输出候选、英文 gloss、轻提示或拒答，不伪造确定中文。 |
| AC-09 | 已会表达不常规提示；保温抽检失败后重新激活。 |
| AC-10 | 阅读正文不出现强制答题弹窗；回顾可跳过、关闭和调整。 |
| AC-11 | 静态页面、SPA 与无限滚动新增正文被增量处理；禁止区域和已处理节点不重复包装。 |
| AC-12 | Ollama/LM Studio 未配置、关闭、超时、断连或返回无效结构时，词典和阅读主路径仍可用；非 loopback 请求为零。 |
| AC-13 | 48 MB 触发整理、64 MB 停止新增可淘汰缓存；静态词典和受保护核心不计入该预算，核心状态不丢失。 |
| AC-14 | 生词本只含尚未确认掌握的表达义项：初测确认薄弱、用户标记“不会”或复测／回顾失败时进入，“不会”立即入本；用户明确“我会了”或同一表达义项新语境直接复测正确时移出。预测、普通曝光或查看释义不自动改变词本，且词本没有“正在学习”等阶段状态。可按英文表达或中文短释义搜索，单条“我会了并移出”可撤销；`vocabulary.csv` 只导出当前词本，`profile.json` 导入空库后恢复语义等价的学习状态、摘要、代表语境和设置。 |
| AC-15 | 不保存完整网页正文、普通浏览历史或来源追溯元数据（URL、页面标题、域名、路径等）；生词本、CSV 导出和可恢复备份不依赖这些字段。 |
| AC-16 | “越用越聪明”必须同时报告误提示、错误释义和明确反馈保持；独立本地语境审计集中“不懂且影响理解”表达的系统识别率达到 95% 以上，个人目标词汇集合在新语境复测中的基本认识率达到 95% 以上。不得以主动补标、普通曝光、点击或提示减少替代这两个指标。 |
| AC-17 | 强提示按当前可见及近可见正文的实际行内负担动态控制；普通超额候选降为下划线加悬停/点击查看，用户明确“不会”的表达不得因预算隐藏。固定词数（含 250）不得作为默认预算。 |
| AC-18 | 核心词典包随扩展可用；长尾包只能在用户明确操作后于本机安装并通过来源、许可证和哈希校验，不得静默下载或安装。 |
| AC-19 | 缓存、词典或模型不得覆盖用户明确反馈或同一表达义项的直接复测；同义项释义与代表语境合并时，正确性／来源可靠性优先于版本新旧，版本新旧优先于文本简洁。 |

## Testing Decisions

测试以阅读辅助协调器的可观察结果为中心：给定正文增量、词典、个人状态、证据和用户动作，断言标注、状态更新、模型任务与审计记录；不测试内部算法的私有步骤。

- 建立人工金标 fixture，重点覆盖 `run`、`running`、`runner`、`rerun`、`run into`、多义词、短语、俚语、词形和错义项。
- 对初测、我会、不会、查看释义、复测、普通曝光、保温抽检分别验证证据语义；直接反馈不得被模型或群体先验静默覆盖，普通曝光绝不能直接晋级为掌握。验证一般测评不覆盖直接反馈、同一表达义项的较新直接复测作答可以覆盖，以及撤销恢复此前有效状态。
- 验证初测确认薄弱、用户“不会”、复测／回顾失败都会进入生词本，用户“不会”立即可见；只有用户明确“我会了”或同一表达义项新语境直接复测正确才移出。系统仅预测未知、普通曝光或仅查看释义均不自动改变词本；词本不维护学习阶段状态。
- 验证按英文表达和中文短释义搜索均只返回当前词本词条；在词本中执行“我会了并移出”后，页面提示、词本和 CSV 同步更新，撤销后恢复此前有效状态。
- 验证 CSV 只含当前词本、已移出词条不会泄漏进 CSV；“数据与隐私”页不显示或搜索代表语境／单条证据，清空可淘汰缓存和全量重置按各自边界生效。
- 验证缓存合并不能覆盖用户直接反馈或同一表达义项直接复测；为同一义项选择释义或代表语境时，正确性／来源可靠性优先于版本新旧，版本新旧优先于文本简洁。
- 验证首次行内中文、重复下划线、新章节再次提示、即时“我会了”删除、即时“不会”标注、撤销和刷新后的持久化；强提示必须为 `cat（猫）` 这类同一行内文本，不得注入 `<br>`、独立翻译块或主动换行。
- 用同一正文 fixture 比较可见/近可见区、段落/结构块、250 词桶三种预算作用域；除作用域外保持候选排序和释义长度不变。记录普通候选的强/轻降级、局部提示聚集、宿主自然回流或布局影响、用户主动关闭/收起、漏标/错义项和可跳过的阅读打断反馈，只有完整性、干扰和主观阅读体验均不劣的策略才能成为默认值。
- 使用静态、SPA 与无限滚动正文 fixture；验证代码、导航、表单、评论和扩展节点不会被扫描。
- 用真实 localhost 协议或忠实本地 fixture 覆盖 Ollama/LM Studio 的未启动、模型不存在、超时、取消、无效结构与中途断连。断言其永不阻断词典阅读路径，也不连接非 loopback 地址。
- 词典构建必须有来源、许可证、版本、哈希、行数、解析错误、重复/冲突/丢弃报告和覆盖报告；更新前后对金标与覆盖 fixture 做回归比较。
- 验证 IndexedDB 升级、异常中断、容量 48/64 MB、缓存清空、完全重置、`profile.json` 恢复与 CSV 导出。
- 性能测试记录长文扫描耗时、单批主线程耗时、增量 DOM 数和布局影响；精确性能阈值在首轮 dogfood 基线后确定。
- dogfood 评价必须同时记录误提示、用户手动补标的漏标、错误释义、回顾正确率、提示密度和阅读流畅度；“提示变少”不能单独通过验收。

## Out of Scope

- Chrome Web Store 发布、账号、登录、云同步、多人协作、社区或排行榜。
- 云模型、远程翻译、整页翻译、浏览记录收集或任何云端上传。
- PDF、视频字幕、电子书、OCR、跨域 iframe、浏览器内置页。
- 作为 V0.1 工程范围决定，不实现完整神经 MWE/WSD、深度知识追踪、跨用户协同过滤或大规模训练；未来可在有真实序列数据后重新评估。
- 未经许可与逐条来源审计的默认词典数据。
- 移动端、Firefox/Edge 发布与商业化支付功能。

### 建议实施顺序

1. 构建词典数据 PoC：先冻结 Codex→Hermes→Reasonix Harness，再完成总计 500 条的清洗工厂 bootstrap；前 100 条是其中的合同 smoke，通过 Codex Gate 后按 100 条里程碑继续，每个里程碑由 Hermes 记录失败模式并提出候选 Skill 修订。500 条只验证流程和数据合同，不等于正式覆盖规模，未经新门禁不得扩到 1000 条。
2. 以 PoC 证据重新执行 `/to-spec`；只有规格再次获接受后，才建立阅读辅助协调器及本地持久化，先完成手动“会/不会”、本地词典和正文增量标注。
3. 加入固定 50 项初测、表达义项状态、回顾与保温抽检。
4. 接入 Ollama/LM Studio、最小充分语境、模型队列与数据审计页。
5. 用真实 dogfood 设定提示预算、模型阈值、容量评分和验收门槛。

本规格与《V0.1 开发计划》《V0.1 验收与测试计划》共同记录已收口的产品决策；下一步先以可丢弃 `/prototype` 按“冻结 Harness → 第一阶段共 500 条（前 100 条为合同门）→ 每 100 条反思并沉淀候选 Skill”的顺序验证词典映射与清洗，再重新显式执行 `/to-spec`。Issue tracker、默认标签和 single-context 已确认；执行 `/to-tickets` 前仍须创建远端 triage 标签并确认本轮 Issue 发布范围。生产编码前还须由用户明确授权并显式执行 `/implement`。
