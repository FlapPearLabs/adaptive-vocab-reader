# 浏览器词汇学习插件 V0.1 验收与测试计划

状态：产品级规则已由可用等价 Grill 流程收口；数值门槛仍按 PoC/dogfood 流程冻结，待词典映射／清洗 PoC 后重新显式 `/to-spec` 定稿。

上游：[V0.1 产品规格](v0.1-产品规格.md)、[V0.1 开发计划](v0.1-开发计划.md)、[RULES.md](../RULES.md)。

解释顺序：若本文与 `RULES.md` 或产品规格冲突，以 `RULES.md` 的已确认项和产品规格为准；本文负责把它们变成可执行验证。

## 1. 验收原则

- 测试最高可用 seam，优先穿过阅读辅助协调器或真实浏览器交互，不对私有算法步骤做脆弱断言。
- 每个硬规则必须有自动化测试或可重复人工协议；“看起来能用”不算证据。
- 真实失败路径与降级和正常路径同等重要。
- 未经 PoC 或 dogfood 校准的数值不得伪装成已确认门槛。
- “提示减少”不能单独证明模型变聪明；必须同时审查误提示、漏标、错误释义和明确反馈保持。概率校准是当前推荐补充指标，待正式 `/to-spec` 选择方法。

## 2. 行为验收矩阵

| --- | --- | --- | --- |

| AC-02 | 主动重新测评 | 初测结束后直接进入阅读；只有用户主动发起的重新测评可以更新先验，不得把初测遗留题强制插入阅读 | 硬规则；重测题型待 PoC |

| AC-04 | 误提示反馈 | 标记“我会了”后，当前选中处及当前页面中高置信识别为同一表达义项的提示立即消失，未来默认隐藏；不同义项、MWE、派生词和身份不确定的实例不被隐藏 | 硬规则；高置信身份判定的 fixture 待 PoC 冻结 |
| AC-05 | 漏标反馈 | 圈选单词/词组标记“不会”后立即进入显示、状态和复习闭环 | 硬规则；缺词占位文案待原型 |

| AC-07 | 表达义项隔离 | `run` 不自动隐藏 `run into`、`rerun` 或不同义项 | 零容忍；屈折/透明派生正向共享待 PoC |
| AC-08 | 语境不确定 | 无可靠义项时显示候选、英文 gloss、轻提示或拒答，不输出伪确定中文 | 零容忍 |
| AC-09 | 保温抽检 | 已会表达不常规提示；抽检失败后重新激活 | 硬规则；间隔与强度待 dogfood |
| AC-10 | 阅读主路径 | 无强制答题弹窗，回顾可跳过、关闭和调整 | 硬规则 |
| AC-11 | SPA/无限滚动 | 新正文增量处理，禁止区域和已处理节点不重复包装 | 硬规则 |
| AC-12 | Provider 降级 | 未配置、关闭、超时、断连、无效结构均不阻断词典路径 | 零容忍 |
| AC-13 | 数据容量 | 48 MB 触发整理，64 MB 停止新增可淘汰缓存，受保护核心不丢失 | 硬规则；字节核算待 PoC |
| AC-14 | 生词本、导出恢复 | 初测确认薄弱、用户标记“不会”、复测／回顾失败的表达进入生词本；“不会”立即可见。仅用户明确“我会了”或同一表达义项新语境直接复测正确才移出；预测、曝光或查释义不自动改变词本，且不维护学习阶段状态。英文／中文短释义搜索准确，单条“我会了并移出”可撤销，CSV 只含当前词本，JSON 在空库恢复后重建语义等价的完整个人数据 | 硬规则 |
| AC-15 | 隐私持久化 | 不保存完整网页正文、普通浏览历史或 URL、标题、域名、路径等来源追溯元数据；生词本与导出不依赖这些字段 | 零容忍 |
| AC-16 | 越用越聪明 | 同时报告误提示、错误释义和反馈保持；独立本地语境审计集中“不懂且影响理解”表达的系统识别率达到 95% 以上，个人目标词汇集合在新语境复测中的基本认识率达到 95% 以上；不得以主动补标、普通曝光、点击或提示减少替代 | 两个 95% 目标是硬规则；抽样、复测间隔、样本量和误差待 dogfood |
| AC-17 | 提示预算 | 按当前可见及近可见正文的实际行内负担控制强提示；普通超额候选降为下划线加悬停/点击查看，明确“不会”的表达不因预算隐藏；固定词数（含 250）不是默认预算 | 作用域与直接反馈保护是硬规则；局部密度、间隔、缓冲和排序权重待 dogfood |
| AC-18 | 词典包安装 | 核心包直接可用；长尾包仅在用户明确操作后本机安装并校验来源、许可证和哈希 | 硬规则；不得静默下载/安装 |
| AC-19 | 证据与缓存合并 | 缓存、词典或模型不覆盖用户明确反馈或同一表达义项直接复测；同义项内容冲突时，正确性／来源可靠性优先于版本新旧，版本新旧优先于文本简洁 | 硬规则；具体置信度与代表句评分待 PoC |

## 3. 分层测试策略

### L0：词典构建与数据质量

测试输入是固定的上游小型 fixture 与构建配置，输出是规范词典包、清单和质量报告。

在任何 Hermes／Reasonix 清洗调用前，Codex 必须独立验证并固定 Harness：`TASK_CONTRACT`、`DATA_POLICY`、`PERMISSIONS`、`ACCEPTANCE`、`BUDGET`、`STATE`、`GOLDSET_POLICY` 与 `STOP_CONDITIONS` 均有内容哈希；Hermes／Reasonix 只读真相源、只写白名单目录，不能读取隐藏审计集、修改阈值或自批阶段。第一阶段总计 500 条，前 100 条是其中的合同 smoke，通过后才按 100 条里程碑继续；每个里程碑必须保存 Hermes 的流程、失败案例、反思、修复与候选 Skill 版本，由 Codex 判定是否继续，未经新门禁不得超过 500 条。每轮还必须保存 Reasonix/DeepSeek 的输入输出 Token、cache-hit Token、人民币成本、request/run ID 与失败重试记录；达到 60/80/95 元阈值时分别预警、冻结新增实验、停止新增调用。

硬门禁：

- 每个数据包记录来源、快照、许可证、获取时间、源哈希、产物哈希和构建版本；
- 用户可显示记录严格限定为 `expression / pos / short_zh`；例句、发音、词源、考试／CEFR、领域、学习阶段、难度和精确词频不得混入。来源／义项指针、哈希、接受／拒绝原因、Schema／Skill／模型版本与成本必须保存在独立审计外壳；
- Hermes 实际执行并调用 Reasonix／DeepSeek；不得调用 Claude Code 或其它现成清洗 Skill。只允许本机可验证的 `skill-creator`，或本轮自己沉淀且经 Codex 审查的 Skill；
- Wiktionary/Kaikki 衍生包保留上游署名、适用许可证和本项目变更说明；许可不清的组合不得进入发布包；
- 每个可显示义项可追溯到上游条目；OEWN/COW 不直接成为页面中文；
- 相同输入产生相同产物哈希；解析、合并、冲突、隔离和丢弃均有计数和原因；
- 无来源、无许可证引用、非法主键或 schema 无效的记录不能进入核心包；
- 金标覆盖 `run/running/runner/rerun/run into`、词性冲突、多义词、MWE、俚语和无可靠中文；
- 数据更新生成条目增删改、schema/覆盖变化、金标回归和回滚证据。
- 核心包与长尾包分别验证 manifest、许可证和内容哈希；无用户明确动作时长尾包下载/安装请求数为零。

PoC 后冻结：目标语料覆盖率、人工义项准确率、核心包体积、冷启动、查询延迟、短释义长度、长尾边界和允许回归幅度。第一阶段 500 条中，前 100 条只验证合同与 Harness，其余按 100 条里程碑暴露分层失败、迭代流程并沉淀 Skill；整批仍不是正式覆盖承诺。

覆盖报告至少分别给出：精确表达命中、lemma 命中、屈折展开命中、仅有英文 gloss、存在可靠简中、MWE 候选命中和完全缺失；不得只报一个无法解释的总覆盖率。

### L1：阅读辅助协调器

使用内存 Adapter，给定正文增量、词典候选、个人状态与事件序列，断言标注决策、状态更新、复习候选和 Provider 任务。

必须覆盖：

- 固定 50 项初测产生的初始先验、不充分校准时的高召回策略和成本敏感提示；
- 我会、不会、测评、复测、查看释义、普通曝光、保温抽检分别记录；
- 初测确认薄弱、用户“不会”与复测／回顾失败进入生词本，用户“不会”立即可见；仅用户明确“我会了”或同一表达义项新语境直接复测正确才移出；预测未知候选、普通曝光和仅查看释义均不自动改变词本，且不维护学习阶段状态；
- 英文表达和中文短释义均可搜索当前词本；词本中的“我会了并移出”与页面直接反馈同样可撤销，并让页面提示、词本和 CSV 恢复此前一致状态；
- 用户直接反馈优先于模型、表达关系和群体先验；同一表达义项以最新明确用户动作优先，撤销恢复此前有效状态；一般测评不得覆盖直接反馈，只有同一表达义项的明确直接复测作答才可覆盖；
- 普通曝光永不直接晋级；
- MWE/粗义项优先于组成词传播；派生只作为待校准证据；
- 低语义置信拒绝强翻译；
- 强提示控制器以当前可见及近可见正文的局部行内负担为作用域；段落/章节只做语义去重，普通超额候选降为轻提示，用户“不会”始终例外；
- 直接反馈在模型更新前后都可审计；
- 当前可信状态不受缓存淘汰影响。

### L2：Adapter 合同

- TextSource：正文、章节、增量和排除区域的规范输出；
- Dictionary：表达＋语境线索到 `expression / pos / short_zh` 或“无可靠中文”；来源与义项追溯只走独立构建审计路径；
- Store：事务、版本迁移、异常中断、容量核算和原子恢复；
- Provider：Ollama/LM Studio 的结构化请求、取消、超时、无效响应和断连；
- Renderer：节点绑定、异步版本校验、即时移除/插入和样式隔离。

### L3：真实浏览器 E2E

固定页面 fixture 至少包括：

- 约 1,500 词、10,000 词和超长正文；
- 导航、代码、表单、评论、隐藏节点、`contenteditable` 和扩展自身节点；
- SPA 正文替换、Mutation burst、无限滚动和重复通知；
- 页面切换或目标节点删除后 Provider 才返回；
- 极端网站 CSS、用户跨节点文本选择、刷新和扩展重载。

必须断言：禁止区域不扫描、节点不重复包装、页面切换后结果不回写、刷新后状态一致、主页面在 Provider 失败时仍可阅读。

### L4：真实协议与安装态

- Ollama 和 LM Studio 分别通过真实 localhost 服务或忠实协议 fixture 验证；
- 验证 Chrome 实际权限、service worker 生命周期、IndexedDB 持久化和可加载构建；
- 构建产物从干净目录安装，完成测评、正文标注、反馈、重启、导出和恢复 smoke；
- 测试命令与 CI/本地门禁在技术栈确定后记录到 `AGENTS.md`。

## 4. “越用越聪明”的测量合同

仅统计用户主动纠错会产生选择偏差，不能据此宣称真实召回改善。产品已确认两个不可互相替代的 95% 指标：独立本地语境审计集中“不懂且影响理解”表达的系统识别率，以及个人目标词汇集合在新语境复测中的基本认识率。当前推荐在下一轮 `/to-spec` 冻结本地、按时间顺序的 prequential 评估，用于生成和审计这些指标；它是测试设计建议，不是两轮 Grill 中用户逐项确认的算法：

1. 在应用当前反馈之前，为“随后获得用户反馈/复测标签”的样本或用户主动加入的 dogfood 审计样本记录表达义项 ID、模型/词典版本、未知概率、显示决策、义项来源和置信度；
2. 用户反馈或复测成为标签后再更新模型，禁止用答案污染预测；
3. 分开报告“直接记忆”和“泛化能力”：前者检查明确标记过的表达，后者只检查未直接标记的新表达、义项或 MWE；
4. dogfood 中加入少量可跳过的盲审样本，同时抽取已提示和未提示表达，避免只能看到系统选择展示的样本；
5. 使用固定回放集比较模型版本，防止网页内容变化被误当作模型改进。

该评估不得变相建立普通浏览历史：未获得标签的普通页面只保留不含 URL、标题或原句的聚合计数；可回放的原始句子仅来自用户主动选择的本地审计集或已允许保存的代表语境，并受 3/12 与 64 MB 规则约束。评估数据的查看、清理和导出边界必须与“数据与隐私”页一致。

至少记录：

| 指标 | 定义与限制 |
| --- | --- |
| 误提示率 | 审计样本中提示但用户认识的比例 |
| 系统未知表达识别率 | 独立本地语境审计集中，用户随后明确为“不懂且影响理解”的表达义项实例里，系统已在标签出现前识别并提供至少轻提示的比例；目标 95% 以上，不能仅用主动补标替代 |
| 用户基本认识率 | 个人目标词汇集合中，在新语境复测获得正确明确确认的比例；目标 95% 以上，普通曝光、查看释义或点击均不计入 |
| 错误释义率 | 被审计行内释义中当前义项错误的比例 |
| 明确反馈保持率 | 再次遇到同一表达时正确执行会/不会的比例 |
| 概率校准 | Brier score 或等价指标；检查概率而非只有二元结果 |
| 提示密度 | 每 1,000 个正文词的强提示和轻提示数量 |
| 阅读流畅度 | 用户主观评分、主动中断与完成情况的本地记录 |

样本量、统计窗口、置信区间方法和通过阈值在基线期后冻结。用户已确认的产品硬门禁是不得只看提示变少，且不能通过牺牲漏标、误提示或释义正确性伪造改善；更新前记录、防数据泄漏和直接记忆/泛化分开是当前推荐验证方法，待正式 `/to-spec` 固化。

## 5. DOM 与性能证据

每次代表性 E2E 记录：首次标注时间、Mutation 到标注完成时间、单批主线程 p50/p95/max、Long Task 数、新增 DOM 节点数、重复包装数、布局影响和长时间滚动后的内存增长。

视觉预算 fixture 还必须断言：强提示是同一行内的短文本，注入的 `<br>` 与独立翻译块数量为零；在相同候选和排序下，可见/近可见区、段落/结构块、250 词对照三种策略只改变预算作用域。分别记录强/轻降级、局部提示聚集、宿主自然回流或布局影响、用户“不会”例外、漏标/错义项与可跳过的阅读打断反馈；只有完整性、干扰和阅读体验均不劣的策略才能作为默认值。

“禁止扫描噪声、禁止重复包装、过期结果不回写”是硬门禁。具体毫秒、内存和布局阈值必须在代表设备 PoC 后冻结；旧草案中的 16 ms 不能直接作为当前已确认阈值。

## 6. Provider 与隐私负例

- 使用标准 URL 解析并精确验证 hostname；拒绝 `localhost.evil.com`、用户名伪装地址和非 loopback IP；
- 拒绝重定向到非 loopback 地址；
- content script 不直接访问 Provider，请求只由扩展后台发起；
- 可靠词典命中、Provider 关闭或目标页面失效时 Provider 请求数为零；
- 请求体只能含目标表达、所在句、触发条件满足时的相邻句、候选义项和必要配置；不得含 URL、标题、整段正文或普通历史；
- 默认只含目标所在句；分别验证指代、省略、引语续接、强义项冲突和用户主动请求会触发相邻句扩展，且最多三句；仍不足时拒绝伪确定释义；字符/token 上限待 PoC；
- 后台并发为 1，支持去重和取消，输出标为“本地模型解释”。
- 队列已有后台补全任务时，用户手动“不会”或“结合上下文解释”请求必须先于尚未开始的后台任务执行；页面失效的低优先级任务可取消。
- 返回结果只允许更新请求绑定且版本匹配的目标表达，不得触发整页重新扫描或翻译；目标失效时丢弃结果。

## 7. IndexedDB、缓存、导出与恢复

必须覆盖：

- 新库创建、版本迁移、迁移中断、事务失败和损坏记录；
- 同一“表达＋粗义项”的第 4 条代表语境和第 13 条近期证据进入时仍满足 3/12 上限，旧详情形成摘要；
- 48 MB、64 MB 状态转换；64 MB 后核心状态和最小摘要仍可写入且不被淘汰；
- 缓存、词典或模型输出均不得覆盖用户明确反馈或同一表达义项的直接复测；同义项内容冲突时，正确性／来源可靠性优先于版本新旧，版本新旧优先于文本简洁；
- 清空缓存不改变当前可信状态，全量重置必须二次确认；
- `profile.json` 导入空库后恢复语义等价状态；缓存无需备份；
- 无效版本、截断 JSON、重复 ID、部分非法记录和恢复中断不产生半恢复状态；
- CSV 正确处理中文、逗号、引号和换行，且至少含表达、短释义和复习信息，不含“正在学习”等阶段状态；
- CSV 只含当前词本，已移出词条不在其中；“数据与隐私”页不展示或搜索代表语境／单条证据，清空可淘汰缓存和全量重置严格遵循各自边界；
- CSV 与 `profile.json` 都不含 URL、标题、域名、路径或其他来源追溯元数据；
- 导出只由用户主动触发，全程不产生网络请求。

容量核算、代表语境选择、低价值评分、恢复替换/合并策略、历史版本支持和性能门槛先由 P6 PoC 冻结。

## 8. Dogfood 协议与退出门

推荐流程：

1. 基线期采集同类文章和固定回放集表现；
2. 根据基线确认连续两周正式观察期的通过门槛；
3. 连续两周正式期冻结模型、词典和规则版本记录，允许正常在线学习但保证预测先于标签记录；
4. 复盘误提示、漏标、错义项、MWE、回顾、延迟、提示密度和主观流畅度。

正式退出前必须满足：全部零容忍/硬规则通过；无隐私越界、核心数据丢失或阅读阻断缺陷；“越用越聪明”的指标不靠牺牲另一项或隐藏更多词制造改善。精确数值在基线后由用户确认并写回本计划和 `RULES.md`。

## 9. 验收证据包

每个阶段应保存：测试命令与结果、fixture 版本、词典 manifest/质量报告、浏览器 E2E 报告、Provider 请求快照、存储迁移与恢复报告、性能基线、dogfood 指标报告和固定基点 code review。未经明确授权不得将这些证据上传或发布。
