# 路线 B 本地模型原型结果（2026-07-17）

## 问题与候选

问题不是“能否整句英译中”，而是：模型能否只根据**目标表达＋完整句**，返回适合 `cat（猫）` 行内显示的简中短释义，并在无法判断时安全拒答。

在“参数量严格小于 4B、英文转简体中文、本地 LM Studio 可直接接入”三个条件同时成立时，未找到可直接采用的翻译专用模型。因而实测候选为通用指令模型 **Qwen3-1.7B（LM Studio 8-bit MLX 变体）**；它不被包装为词典，也不成为核心词库。

## 本机运行证据

- `lms load qwen/qwen3-1.7b --context-length 1024 --yes`：加载成功，29.52 秒，运行时报告 1.72 GiB。
- 1024 token 载入前估算：总内存约 2.40 GiB；本机 16 GB 内存可以载入。
- 仅启动 `127.0.0.1:1234` 的 LM Studio OpenAI 兼容接口；未向外部服务发送任何文本。

## 三轮观察

前两轮不是质量结论，而是发现并修正输出契约歧义：

1. 最初提示下，16/16 返回合法 JSON，但全写 `need_more_context`，即便句子已经足够。
2. 明确“完整句通常必须作答”后，模型给出了正确中文，但仍会将非空释义与 `need_more_context` 同时输出。
3. 加入互斥契约“`short_zh` 非空则 `status=answer`”后，以相同 16 个案例重跑：16/16 JSON 合法，12/16 命中当前严格的自动可接受表；逐例人工复核为 14/16 可接受。

两项自动金标缺口是词表本身太窄，不是模型错误：`put off → 延后`、`stems from → 来自`。两项实质性错误为：

- `She runs a small publishing company.` 中 `runs → 跑`，没有选中“经营/管理”。
- `The policy is aimed at reducing pollution.` 中 `aimed at → 减少污染`，复述了句中目标，没有解释表达本身“旨在/针对”。

另外，同一 `addressed + 原句 + 原提示` 的第二次请求命中进程内缓存，延迟为 0 ms。这只证明了**同输入**缓存读取；并未验证不同义项隔离、缓存迁移或持久化。

## 基线审查修正

上面的 `16/16 JSON 合法` 只描述当时响应可以解析且字段形状存在，不能证明完整输出合同已经由客户端执行。提交基线前已补上客户端合同校验：目标表达必须原样回显，`answer` 必须配非空短释义，`need_more_context` 必须配空短释义，短释义最多六个字符；任一失败都不得自动命中。Provider 地址也改为标准 URL 精确解析，并拒绝任何重定向，避免伪 loopback 域名越界。

这些修正没有重新调用模型，因此不改写上面的历史 12/16 自动命中与 14/16 人工可接受数字。扩大 PoC 必须用修正后的客户端重新生成结果，不能把旧数字当作新合同的通过率。

## 结论

**路线 B 可以进入扩大 PoC，但只能作为受限兜底，不是词典替代品。**

- 核心高频可审计包仍负责普通即时行内提示。
- 模型只处理核心包缺失、MWE/习语、义项冲突或用户主动请求。
- 输出必须由客户端验证：JSON 字段齐全、`status` 与 `short_zh` 互斥、短释义长度受限；验证失败时不显示强提示。
- 不能因模型给出中文就相信义项正确；`run a company` 是必须保留在后续金标集的反例。
- 缓存键至少绑定表达、充分语境/义项、模型 ID、提示契约版本；不得退化为永久的 `单词 → 中文` 映射。

这 16 条手工冒烟集没有统计证明力。下一步应先冻结 Codex→Hermes→Reasonix Harness；第一阶段总计 500 条，先用其中 100 条验证合同与权限，通过 Codex Gate 后按 100 条里程碑继续，并由 Hermes 反思、修正流程和沉淀候选 Skill。整批用于测试正确义项、错误强提示、拒答、结构化输出、延迟及跨义项缓存隔离，不是正式覆盖证明；未经新门禁不扩到 1000 条。
