# D：无视觉词交互原型结果（可丢弃）

## 结论

**推荐后续实施阶段优先采用路线 1（全量无视觉包装）作为候选，路线 2（pointer/caret 动态定位）不建议作为唯一的悬停/点击实现。**

这只是原型推荐，不是 D 的最终实现选择，也不修改 `RULES.md`、Spec 或生产代码。原因是路线 1 在本次真实 Chrome 的十个目标场景中精确命中 10/10；路线 2 虽然没有正文扫描和 DOM 增量，却在开放 Shadow DOM 直接失效，并在长文滚动场景把指针所在的 `Ability` 误解析为相邻的 `improve`。这两项都破坏 AC-1/AC-2 的核心正确性，不能用“DOM 为零”抵消。

## 实验边界与复现

- 浏览器：Chrome for Testing `151.0.7922.47`，隔离 profile，1280×800 headless viewport。
- 词典：只读取现有 `data/derived/ecdict-core-1000/`；1,000 主词条、1,505 forms alias；没有下载或集成全量 ECDICT。
- 一键运行：`node run-experiment.cjs`。
- 原始机器数据：[measurements-2026-08-07.json](measurements-2026-08-07.json)。本报告中的时间是一次原型运行的实测值，不能当作生产性能预算。
- tooltip 是原型的四行本地显示（词形、音标、词性、中文释义）；点击实际打开“不会”按钮并触发本地反馈文案，不持久化任何状态。

## 无法由任一路线单独消除的硬边界

1. **跨源 iframe**：本原型只验证同源 iframe。两条路线都不能绕过浏览器同源隔离；未来是否支持取决于扩展注入权限、frame 可访问性和具体页面策略，不能在内容脚本中假装统一可达。
2. **封闭 Shadow DOM**：路线 1 只能扫描已可访问的开放 root；路线 2 在本次测试中连开放 root 都失败。封闭 root 对两者都不是可保证范围。
3. **运行期新建的 Shadow root**：路线 1 当前原型会扫描初始化时已存在的开放 root，但 document 的 MutationObserver 不会自动观察新的 shadow tree；需要额外生命周期策略，不能把本次静态 Shadow DOM 通过误述为动态 Shadow DOM 支持。
4. **站点 CSS 与大页面容量**：无样式 span 不引入本原型中的 layout shift，但真实网站可对 `span` 施加选择器规则，且查询词典扩容可能远超本 fixture 的 3,891 token。最终路线前仍需真实网站样本、CSS 隔离和长文性能复测。
5. **tooltip 算法不是路线区分项**：本原型使用了安全区/翻转定位，因此 AC-8 的几何通过不能证明生产 tooltip 已修复；它仅确认两条交互路线都能把正确目标矩形交给一个可行的定位算法（caret 的两个失败场景除外）。

## 对后续决策的含义

路线 1 的主要代价是 DOM 增长，且这次 +3,888 节点的数据必须在真实网页上复测；但它提供确定的 token 边界、直接的事件目标，并可通过同源 iframe 的独立注入与开放 Shadow root 的显式扫描获得可验证路径。路线 2 的优势（零扫描、零正文节点增长）成立，但所测的 Shadow DOM 和滚动命中失败意味着它若要继续，需要复杂的 fallback / root 分派 / 误命中防护，已偏离此项目要求的最小实现。

因此，若 D 在后续发现与对齐阶段被确认，建议把“**透明包装 + 事件委托，针对开放 Shadow DOM 与同源 iframe 明确处理；先以真实长文重测 DOM/CSS/性能**”作为待批准的实现候选，而不把 pointer/caret 作为唯一交互基础。
