# 06 — 人工 dogfood 验收门

**权威来源**：
- [V0.1 重新对齐规格](../../../docs/specs/2026-07-30-V0.1-重新对齐规格.md)
- [RULES.md](../../../RULES.md)

**What to build**：一个能真正判断「这个插件对我有没有用」的验收流程和结论；跑完之后由用户自己明确接受或拒绝，而不是被测试数量说服。

**Blocked by**：05 — 真浏览器综合验收门

**Status:** ready-for-agent

**用户可见收益**：一个能真正判断「这个插件对我有没有用」的验收流程和结论；跑完之后由用户自己明确接受或拒绝，而不是被测试数量说服。

**目标**：按固定门槛执行人工 dogfood 并取得用户明确结论。

**主责任 Requirement ID**：R-DOG-1～R-DOG-5

**依赖和 blocker**：
- 依赖：T5。
- Blocker：T5 —— 未通过真浏览器验收门不得进入人工 dogfood。

**开始 T6 之前增加真实用户升级门（强制，引用修正后的 Spec §20.5）**：
- 取得用户明确授权；
- 备份真实 chrome.storage snapshot；
- 验证副本可解析且保留 schema 2 内容；
- 实际执行时机为 T5 隔离真浏览器 E2E 全绿之后、T6 人工 dogfood 开始之前、真实 profile 首次加载 schema 3 构建之前；
- 然后才允许真实 profile 首次加载 schema 3 构建。

> 当前（本轮发布时）真实用户快照备份仍未执行。

**范围**：
- 产出人工记录清单模板；
- 按固定门槛执行——连续 7 天、每天至少一篇真实英文网页、累计至少 20 篇；
- 每篇最多人工抽查 20 个相关词，分别记录「不必要提示 / 释义不可用 / 覆盖缺失」三个独立数字；
- 每天另记日期、当天篇数、状态或进度是否丢失、估计是否看得懂且有用；
- 最终由用户明确接受或拒绝。

**明确非目标**：
- **不实现任何遥测、日志平台、上报、dashboard、网页记录或自动统计**；
- 不保存 URL、页面标题、正文、句子；
- 不用自动 E2E 冒充人工验收；
- 未获用户明确接受不讨论 10,000 词扩容。

**预计影响的模块责任**：不涉及生产代码，仅本地记录清单文档（位置待授权，且不属本轮发布范围）。

**Requirement → behavior → test seam**：

| Requirement | Behavior | Test Seam |
|---|---|---|
| R-DOG-1 | 连续 7 天、每天至少一篇、累计至少 20 篇 | 人工验收记录 |
| R-DOG-2 | 每篇最多人工抽查 20 个相关词，记录不必要提示/释义不可用/覆盖缺失 | 人工验收记录 |
| R-DOG-3 | 每天记录日期、当天阅读篇数、状态/进度是否丢失、估计是否看得懂且有用 | 人工验收记录 |
| R-DOG-4 | 不保存 URL、页面标题、正文、句子；不建设日志/遥测/上报/dashboard | 人工验收记录 |
| R-DOG-5 | 由用户明确接受或拒绝；未接受不讨论扩容 | 用户明确确认 |

**数据、迁移或隐私风险**：
- dogfood 期间是真实用户数据；
- 开始前确认 R-MIG-8 旧快照副本（真实用户升级门）已完成且可解析；
- 期间若发现状态/进度丢失，如实记录，作为 dogfood 缺陷和验收风险。

**失败行为 / 缺陷处理（删除未经确认的规则）**：
- 已删除：「状态丢失后立即停止计时」；
- 已删除：「出现缺陷后自动重新开始七天」；
- **正确表达**：发现状态或进度丢失时如实记录，作为 dogfood 缺陷和验收风险；是否中止、修复后续跑或重新计时，由用户根据缺陷严重度明确裁定。

**反过度设计检查**：
- 零代码交付；
- 不建遥测/日志/dashboard；
- 不把人工门自动化；
- 所有「用户签字」表述统一为「用户明确接受或拒绝」，不要求字面签名。

**真实验证命令**：无自动命令。人工验收记录 + 用户明确确认（人工门，不伪装成自动测试）。

**完成定义**：
- 满足固定门槛的完整记录存在；
- 三类数字与每日四项齐全；
- 用户明确给出接受或拒绝；
- 若接受，才可评估扩容或删除冻结审计代码。

## Acceptance criteria

- [ ] 记录满足连续 7 天且累计 ≥20 篇。
- [ ] 每篇三个数字（不必要提示 / 释义不可用 / 覆盖缺失）与每日四项（日期、当天篇数、状态/进度是否丢失、估计是否看得懂且有用）记录齐全。
- [ ] 记录中不含 URL / 标题 / 正文 / 句子。
- [ ] 未新增任何日志或遥测代码。
- [ ] 用户给出明确「接受」或「拒绝」。
