# 个性化浏览器词汇辅助模型：arXiv 证据审查

日期：2026-07-16

范围：只使用 arXiv 原始论文，并用作者页或官方任务页作必要交叉核验；不修改产品规格或代码。

## 结论先行

当前提出的“分层表达图 + 证据账本 + 阅读阻塞风险 + Beta 分层初测”不是坏设计，但还不能称为“已证实的最佳设计”。论文证据支持其中三点：

1. **必须个性化**，群体难度和词频只能当冷启动先验；
2. **必须在上下文中区分单词、MWE 和义项**；
3. **必须允许低置信预测拒答/降级展示**，不能把未经校准的分数直接映射成行内中文。

论文同时反驳或削弱了三点：

1. 一个手工乘法式 `BlockRisk` 不能同时承担“表达识别、义项判断、用户会不会、是否值得打断”四种不同错误；这些任务应拆成级联模型；
2. `词频层 × 表达类型` 的 Beta 后验适合作为冷启动统计，不足以成为长期掌握模型；它忽略题目难度、上下文、义项和时间变化；
3. “透明派生词自动继承并隐藏”缺少直接证据。形态和语义透明度相关，但现有模型与人类透明度判断只达到中等一致，派生关系在 V0.1 应作为**软特征**，不能等同明确掌握。

因此建议将核心架构改写为：

> **高召回表达候选器 → 语境义项/MWE 判别器 → 个体未知概率模型 → 成本敏感展示策略 → 证据账本与主动抽检**

表达图继续保留，但职责收窄为“候选关系、特征和证据来源图”，而不是自动传播已知状态的真值图。

## 对现设计逐项审查

### 1. 分层表达图：保留，但改为“候选与证据图”

保留节点：

- `surface / lemma / POS`；
- 粗粒度 sense；
- MWE / phrasal verb / idiom；
- 派生或复合关系。

边的语义应改为：

- `IDENTITY`：同一 lemma、POS、粗义项下的屈折变体，可共享直接状态；
- `EVIDENCE_TRANSFER`：派生/复合透明度只提供一个先验特征；
- `CANDIDATE_OVERLAP`：单词与短语候选重叠，交给上下文模型裁决；
- `NO_TRANSFER`：不同义项、习语和词汇化短语不传播掌握。

关键约束：只有用户明确反馈或复测能写入 `known/unknown`；图关系只能改变先验或展示强度。V0.1 中，即使 `run` 已知，`runner` 也最多从强释义降为轻提示/隐藏候选，不能生成“用户明确已知 runner”的事实。何时可完全隐藏必须由校准数据决定。

### 2. 证据账本：保留，并扩展“证据类型”

建议分开保存：

- `direct`: 我会、不会、忽略、复测正确/错误；
- `behavioral`: 展开释义、停留、重复点击，仅作弱证据；
- `inferred`: 词频、CEFR、词形、派生透明度、群体 CWI；
- `semantic`: MWE 命中置信度、WSD 义项置信度、词典覆盖质量；
- `temporal`: 最后确认时间、抽检间隔、遗忘证据。

直接证据优先，推断证据不得覆盖直接证据；普通曝光不等于学会。

### 3. `BlockRisk`：拆成四阶段，不用一个乘法公式

单一乘法公式的问题是：任何一个低分都可能把真正生词压到阈值下；同时它无法区分“用户会不会”和“中文义项是否正确”。建议级联：

1. **表达候选器（高召回）**：字典 MWE、词形、派生和 n-gram 候选全部保留；
2. **语义判别器**：输出 `P(MWE成立)`、`P(义项=s)` 及置信区间；
3. **个人掌握模型**：输出 `P(用户在此语境不懂该表达)`；
4. **展示决策器**：结合漏标成本、误提示成本、错误释义成本和视觉预算选择 `inline / subtle / hidden`。

建议的决策表：

| 个人未知概率 | 语义/释义置信度 | 输出 |
|---|---|---|
| 高 | 高 | 行内短释义 |
| 高 | 低 | 轻提示；点击后展示候选义项或本地模型解释 |
| 中 | 任意 | 轻提示，作为后续主动反馈候选 |
| 低 | 高 | 隐藏；推断已知项进入低频保温抽检 |
| 用户明确不会 | 任意 | 至少轻提示；有可靠释义时强提示 |
| 用户明确会 | 同一表达/粗义项 | 隐藏；不扩散到不同义项/MWE |

阈值不能先写死成 0.35/0.10；应在目标用户数据上按“漏标成本高于误提示成本”的目标校准。产品上用风险—覆盖曲线选择，而不是只优化 F1。

### 4. Beta 分层初测：降级为冷启动先验与监控统计

`词频层 × 表达类型` 的 Beta-Binomial 有三个优点：本地、可解释、小样本可更新。但它假设同一格里的题近似可交换，无法表示题目难度、猜测、上下文和不同义项。

V0.1 建议：

- 保留 Beta 后验，作为“这一类表达大概会多少”的保守先验；
- 个体预测改用可解释的在线逻辑模型/贝叶斯逻辑模型，特征至少含频率、词长、CEFR、POS、表达类型、语境义项不确定性、领域、派生透明度；
- 表达级直接证据作为 override，不被群体模型冲掉；
- 不声称是 IRT/CAT，也不输出伪精确“词汇量 6,237”。

测试流程也应从“固定 56 题”改成“**最多 56 题、允许提前停止**”：

- 约 20–24 道覆盖频率/CEFR 与基本词类的锚点；
- 约 8–16 道根据当前不确定性自适应选择；
- 约 8 道多义词、MWE、透明/不透明派生的语境题；
- 伪词和置信度检查保留；
- 当关键层级后验区间已稳定，或继续提问的预期信息增益很低时提前结束。

Gooding & Tragut 的 23 题结果说明主动学习值得采用，但其任务是孤立词形二元自评；我们的上下文/MWE 目标更复杂，因此不能照搬“23 题足够”，只能把它当作“56 题不必全部固定”的证据。

### 5. 主动学习：加入“未来阅读价值”，不能只抽最大熵

论文中的纯不确定性采样适合离线词池。插件应避免不断询问生僻且几乎不会再出现的词。建议抽检价值函数：

```text
QueryValue(x)
  = 模型不确定性
  × 未来出现概率
  × 对句子理解的重要性
  × 覆盖新区域的多样性
  × 用户交互成本折扣
```

初测和保温抽检都用同一选题框架；阅读时不强插题，而把高价值候选放进侧栏/短回顾。用户在网页上的“会/不会”本身就是最有价值的在线标签。

## 版本修订建议

### V0.1：验证闭环，不训练大型模型

- 采用五段管线：候选、语义、掌握、展示、证据；
- MWE 用词典/规则高召回候选 + 轻量上下文过滤；低置信时降级为轻提示；
- `IDENTITY` 屈折共享可以硬传播；派生、复合、不同义项只作软特征；
- 初测最多 56 题，锚点 + 主动题 + 语境题，支持提前停止；
- Beta 分层仅作先验；个体模型用可解释在线逻辑模型；
- 明确记录每个输出的来源与置信度，支持本地校准；
- 验收至少包含：未知表达召回率、强提示精确率、错误行内释义率、Brier/ECE、风险—覆盖曲线、每千词提示数、阅读中断率。

### V0.2：用真实单用户数据校准

- 训练/校准 `P(未知)` 和 `P(义项正确)`，将阈值按用户选择的“漏标更糟”成本函数确定；
- 学习用户自己的派生迁移系数，但仍禁止推断证据多跳传播；
- 加入未来曝光感知的主动抽检与个体遗忘曲线；
- 建立 token-level 金标集：同一个词在不同语境、不同义项下分别标注。

### V1：有群体纵向数据后再考虑

- 校准题库和真正的 IRT/CAT 或 BOBCAT 类选题；
- 知识追踪模型与个体遗忘参数；
- 经过校准的选择性预测/保形预测；
- 可选的本地行为信号，但不默认启用摄像头或侵入式追踪。

## 不可承诺项

- 不能承诺“初测后覆盖 80% 熟词/生词”——现有论文没有在本产品用户画像、网页域、MWE 和多义词条件下证明这一数字；
- 不能承诺“所有短语/俚语都能识别”——未见 MWE 和新义项仍是开放问题；
- 不能把 softmax 或 LLM 自评当成校准概率；
- 不能把形态透明度当成掌握真值；
- 不能用整体 accuracy 掩盖未知词稀疏问题；至少报告 recall、precision、Brier/ECE 和风险—覆盖；
- 不能在没有题库作答数据时声称实现了心理测量意义上的 CAT/IRT；
- 不能从“用户没点释义”推断“用户会了”。

## 最终判断

现设计的领域边界是对的，但最重要的升级不是再增加更多语言学类别，而是把不同不确定性拆开：

```text
表达是否成立？
当前义项是什么？
用户是否理解？
现在是否值得打断？
```

只有前两项和第三项都足够可信，才显示行内中文；第三项高、前两项不可信时应轻提示并拒绝生成确定释义。这套“级联 + 校准 + 拒答 + 主动学习”比一个统一的表达图分数更符合论文证据，也更贴合“有基础、被少量生词卡住、漏标比多提示更糟”的目标用户。
