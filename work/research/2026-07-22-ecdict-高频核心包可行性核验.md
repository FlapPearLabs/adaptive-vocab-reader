# ECDICT 高频核心包可行性核验

日期：2026-07-22
状态：研究事实；不替代 `RULES.md` 中的产品决定。

## 结论

ECDICT 的公开数据格式足以支持一个本地、约一万主词条的网页词汇提示核心包：运行时可只保留 `word`、`phonetic`、`pos` 和 `translation`；构建期可利用 `bnc`、`frq` 与 `tag` 选择候选，并用 `exchange` 生成独立的常见词形映射。

它**没有**官方定义的“高频一万词”成品清单。因此“高频一万词”必须由本项目冻结一个确定性筛选规则和输入版本后产生，不能声称是 ECDICT 官方排名。

## 官方来源已确认的事实

- [ECDICT README](https://github.com/skywind3000/ECDICT/blob/master/README.md) 将自己描述为英汉双解词典数据库，声明 CSV 使用 UTF-8，并列出 `word`、`phonetic`、`translation`、`pos`、`tag`、`bnc`、`frq`、`exchange` 等字段。
- 同一 README 将 `bnc` 定义为英国国家语料库词频顺序、`frq` 定义为当代语料库词频顺序，且说明 `tag` 包含考试标签；这三项可作为构建期候选排序或过滤输入。
- 同一 README 说明 `exchange` 包含屈折及 lemma 关系，可用于构建期生成 `went → go`、`running → run` 一类映射；运行时无需保留其完整原始编码。
- [仓库 LICENSE](https://github.com/skywind3000/ECDICT/blob/master/LICENSE) 是 MIT 文本，要求在副本或实质部分中保留版权和许可声明。
- README 同时说明数据曾组合来自早期词表、爬取资料、网友贡献、`cdict`、WordNet 与 BNC 等来源。它没有给出每一条中文释义的逐条权利链或再分发证明。

## 本项目中的适用边界

### 可以作为 V0.0 / 个人 dogfood 候选

- 输入：固定提交或发行快照的 ECDICT CSV；记录获取日期和内容哈希。
- 输出：一万主词条的紧凑静态词典，以及由 `exchange` 生成的词形映射。
- 不做 LLM 逐条补全；不完整或异常的候选直接丢弃并从候选池递补。
- 对运行时只要求快速、可用的单词级提示；不承诺语境义项消歧、MWE 或词族掌握传播。

### 仍为 UNKNOWN，不能提前宣称通过

- 将含 ECDICT 释义的扩展公开上架、商用或再分发时，每条内容的完整权利链是否足够。
- 最佳一万词排序规则、音标/词性/中文释义的实测完整率，以及目标网页语料上的覆盖率。
- ECDICT 的词频排序是否最符合本项目实际阅读语料；`bnc` 与 `frq` 如何合并仍是产品选择，而非官方答案。

## 可复现构建建议（尚待产品确认）

1. 固定 ECDICT 输入版本与哈希。
2. 只保留规范化单词条目，要求音标、词性、中文释义均非空。
3. 排除短语、纯专名、缩写、明显异常或超长释义；缺字段即淘汰，不调用模型补齐。
4. 用明确记录的 `frq`/`bnc`/`tag` 规则生成候选排序，选取一万条；输出构建报告（输入数、淘汰数与原因、最终条数）。
5. 从 `exchange` 构建仅指向已选主词条的词形表，防止词形映射指向包外条目。
6. 对最终包随机抽样，人工检查中文释义、词性和音标；抽样口径与通过阈值须由后续 Grill 决定。

该方案的推断是：对于个人本地 dogfood，先以确定性筛选和抽样检查获得可用性，比把一万条数据交给模型逐条改写更符合当前范围；这不是对公开发布许可或词典语义完备性的结论。
