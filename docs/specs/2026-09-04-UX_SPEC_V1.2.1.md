### 1.2 Authority Reconciliation Rules
1. **Canonical `wordKey` Semantics:** `wordKey` represents the repository's existing normalized vocabulary entry key. UX does NOT introduce grammatical or linguistic lemma theories.
2. **Reuse Existing Persistence Contracts:** UX documents MUST NOT specify schema migrations or invent new persistent storage models. The production implementation must map to the repository's established `WordState`, `AssessmentEvidence`, `DictEntry`, and `wordKey` contracts.
3. **Repository `DictEntry` Field Names:** UX binds strictly to established repository field names:
   - `phonetic`
   - `pos`
   - `translation`
   - `effectiveFrequencyRank` (where relevant)
   - Do NOT define `ipa` or `zh` as production field names.
4. **Notebook Semantics:** The Notebook reflects active learning vocabulary as authorized by product specifications. It must not be redefined into an unconstrained dump of all passive or known words.
5. **Normative Privacy Rule:**
   - Ephemeral in-memory processing of host webpage text is required for the reading product and is permitted.
   - **Host webpage text, sentences, URLs, page titles, domains and browsing history MUST NOT be persisted, synchronized, transmitted, logged, or retained beyond the active processing need.**
   - Ephemeral sentence context may be displayed only from current in-memory page context and must never be persisted.

### 2.1 Metadata Resolution Failure Orthogonality (Normative)
`METADATA_RESOLUTION_FAILURE` is NOT a separate vocabulary state and must NEVER be treated as automatically receiving Learning styling.

**Core Invariant:** Metadata resolution failure MUST NOT mutate or override `WordState` or `DisplayDecision`. The existing display state remains authoritative:
- **Known + metadata failure** → Remains plain native text.
- **Light/Hinted + metadata failure** → Remains subtle amber dotted hint; lexical details fail closed.
- **Learning + metadata failure** → Remains subtle amber solid learning underline, but inline Chinese gloss is omitted.
- **Inspection Popover / Tooltip:** May display the restrained fallback string `释义暂不可用`. Zero synthesized placeholder definitions (e.g. never `"word crude"`, `${word}`).

## 3. Typography & Visual Styling (Normative vs. Examples)

### 3.1 Host-Page Typography Non-Interference (Normative)
Host webpage prose typography MUST remain completely unmolested by the extension:
```css
/* Normative: In-situ token wrapper styling */
.vocab-token {
  font-family: inherit !important;
  font-size: inherit !important;
  font-weight: inherit !important;
  color: inherit !important;
  line-height: inherit !important;
  letter-spacing: inherit !important;
}
```
The extension styles **only** its own added visual artifacts: the subtle underlines, the inline gloss span, the floating recovery pill, the inspection popover, the lightweight hover tooltip, and the popup extension window.

### 3.2 Underline Presentation (Normative)
- **Hinted / Unknown Word:** Subtle amber dotted underline.
- **Learning Word (First & Repeated):** Subtle amber solid underline.
- **Engine Freedom:** Engineering may implement this visual result via `text-decoration`, SVG background, or pseudo-elements. The chosen technique MUST guarantee zero layout shift, stable vertical alignment across wrapped lines, and total isolation from host CSS reset stylesheets.
- *Non-normative visual reference:* Warm amber hue approximately `#f59e0b` / `#d97706` with 50%–60% alpha against light reading backgrounds.

### 3.3 Inline Chinese Gloss Presentation (Normative)
1. **Format:** `{posPrefix}{translation}` (e.g., `adj. 短暂的` or `v. 阐明`).
2. **Fixed Contract:** First-occurrence gloss + repeated-occurrence underline-only behavior is the fixed V0.1 interaction contract, not a user setting.
3. **Styling:** Small, restrained editorial italic serif (approx. 11px–12px), muted warm amber/brown tone (e.g., `#78350f` at 60% opacity), `line-height: 1`, `user-select: none`.
4. **Spacing:** Optical gap of approximately 6px (`0.35em`) separating headword and gloss.
5. **Suppression (Fail-Closed):
   - Omitted if `translation` is missing, empty, or unverified in the canonical dictionary.
   - Omitted on repeated occurrences per the fixed V0.1 interaction contract.
   - Omitted if master inline gloss toggle or session assistance is disabled.
6. **Selection Immunity:** Must have `user-select: none` to prevent pollution of user clipboard when copying prose text.

### 3.4 Extension UI Surface Typography (Non-Normative Reference Values)
- **Popover Headword:** Serif, bold, approx. 16px, dark neutral (`#1c1917`).
- **Popover Phonetic (`phonetic`):** Monospace, approx. 11px, neutral muted (`#78716c`).
- **Popover POS (`pos`):** Serif, italic, approx. 11px, neutral muted (`#a8a29e`).
- **Popover Definition (`translation`):** Clean sans-serif, approx. 12px, medium weight (`#292524`).
- **Popover Sentence Context:** Serif, italic, approx. 11px, neutral (`#57534e`), single truncated line.
- **Action Buttons / Pills:** Sans-serif, approx. 11px–12px, single-line nowrap.

## 4. Interaction Contracts

### 4.1 Hinted Word Hover vs. Click Behavior (Normative)
1. **Hover Behavior:**
   - Hovering a Hinted/Unknown word token may display a **lightweight lexical tooltip** showing repository metadata (`phonetic`, `pos`, `translation`).
   - **Hover MUST NOT mutate state.**
   - **Do NOT auto-open the full action popover merely on hover.**
2. **Click Behavior:**
   - Single click on a Hinted or Learning word token opens the full **Word Inspection Popover**.
   - Marking a word as **Known** or **Learning** remains strictly an **explicit click action**.

### 4.2 Word Inspection Popover
1. **Trigger:** Single click on any hinted or learning word token.
2. **Behavioral Geometry (Normative):**
   - **Vertical Priority:** Prefer placement directly **above** the target word anchor.
   - **Flip Behavior:** If vertical viewport space above the anchor is insufficient (< popover height + margin), dynamically flip placement **below** the anchor.
   - **Horizontal Clamping:** Popover must be clamped horizontally within viewport bounds with a minimum 12px safety margin from the screen edge.
   - **Collision Prevention:** Must never occlude the target word itself or protected browser/host chrome.
   - **Scroll Handling:** Dismiss popover or adjust position synchronously on host viewport scroll.
3. **Terminal Actions (Auto-Dismiss):**
   - Clicking **Known** commits the word to `'known'` and **immediately dismisses the popover**.
   - Clicking **Learning** commits the word to `'learning'` and **immediately dismisses the popover**.
   - Neither action requires a secondary confirmation or second click on an 'X' button.
4. **Cancellation Actions (Dismiss Without Mutation):**
   - Pressing **Escape** dismisses the popover.
   - Clicking anywhere outside the popover bounding box dismisses the popover.
   - Clicking the popover **Close (X)** icon dismisses the popover.
   - None of these cancellation actions modify vocabulary status.

### 4.3 Plain-Word "Mark as Learning" Recovery Path
Provides a quiet fallback for unhinted words that the reader wishes to study:
1. **Trigger:** Reader selects text using standard mouse drag or native word double-click.
2. **Strict Selection Validation (Normative):**
   - Take the original native selection string and trim leading/trailing whitespace.
   - **Multi-Word Rejection:** If the trimmed string contains any internal whitespace (`\s`), line breaks, hyphens, or punctuation delimiters, **reject immediately**. Never concatenate or sanitize `"deep reading"` into `"deepreading"`.
   - **Single Token Test:** The trimmed string must resolve to exactly one single lexical word token.
   - **Dictionary Containment Check:** If token matches `QUERY_DICTIONARY_NOT_CONTAINED`, recovery affordance must remain completely silent.
   - If validation fails, do not render any recovery affordance.
3. **Affordance Presentation:**
   - A minimal floating pill button appears centered above the selection bounds.
   - Visual: Dark compact pill (`Mark as Learning · 不会`) with bookmark icon.
4. **Execution Semantics:**
   - Mouse event must intercept `mousedown` with `preventDefault()` and `stopPropagation()` to prevent host selection from clearing before click registration.
   - Query authorized dictionary seam for the token.
   - Commit state to `'learning'` via existing repository seam.
   - Native selection is cleared immediately (`window.getSelection()?.removeAllRanges()`).
   - The affordance vanishes; the word transforms into Learning state on the page.

## 5. Vocabulary Assessment & Estimate Presentation

### 5.1 Assessment Presentation (Normative)
- **Render Repository `QuizQuestion` Contract:**
  - Remove binary "Need Gloss / I Know This" as a normative assessment model.
  - Production assessment UI must render the repository-provided `QuizQuestion` contract:
    1. **Target Word:** Headword under assessment.
    2. **Repository Answer Options:** Display repository-provided candidate options.
    3. **Explicit Unsure Option:** Always present an explicit "Unsure / 不确定" selection.
    4. **Progress Counter:** Display current question progress (`current / total`).
- **Domain Flow Integrity:** Initial Assessment and Daily Calibration remain separate repository domain flows with their existing question/answer contracts and MUST NOT be merged, combined, or redefined. UX must not redefine assessment semantics or question algorithms.
- **Completion:** Clean confirmation indicating assessment flow completion.

### 5.2 Estimate Semantics (Normative)
- **Source of Truth:** Estimate UI must display ONLY values returned by the repository's existing vocabulary estimate domain seam.
- **Prohibited Numbers:** Prototype numbers (`~5,420 words`, `5.4k words`, `receptive vocabulary frontier`) are non-normative design mockups and must NEVER become hardcoded production values.
- **Display Structure:**
  - Standard point estimate accompanied by its conservative lower-upper range as supplied by the engine (e.g. `Estimate: ~X words (Range: Y – Z)`).
  - Explicitly scoped to the active assessment vocabulary package.
  - **Strict Prohibition:** Never extrapolate CEFR rankings (A1–C2), grade levels, or speculative percentile curves.

## 6. Extension Popup Specification (AB1) & Settings Authority

- **Structure:** Fixed compact layout (`320px` width, utilitarian vertical hierarchy).
- **Navigation:** Single-level flat tab bar:
  1. **This Page:** Displays vocabulary detected in current page scope.
  2. **Notebook:** Displays actively tracked learning vocabulary. Provides search filter and quick status toggle.
  3. **Level Check:** Seamless integration with repository Initial Assessment and Daily Calibration domain flows rendering repository `QuizQuestion` items.
  4. **Settings:** Status of settings evaluated below.
- **Settings Authority Status:**
  - `showInlineMeaning`: **OPEN / NOT AUTHORIZED** (requires explicit approval by repository product authority).
  - Current-tab / session assistance toggle: **OPEN / NOT AUTHORIZED** (requires explicit approval by repository product authority; domain names must NOT be persisted).
  - `firstOccurrenceOnly`: **REMOVED FROM SETTINGS** (enforced as a fixed V0.1 interaction contract).
  - `activeDomainEnabled` (persistent per-domain state): **NOT AUTHORIZED**.
  - `pronounceOnHover`: **NOT AUTHORIZED**.
  - `fontSize` extension setting: **NOT AUTHORIZED**.
  - Multi-tiered mobile bottom-sheet behaviors: **NOT AUTHORIZED**.

## 7. Error Handling, Empty States & Fail-Closed Behavior

1. **Dictionary Resolution Failure:**
   - Handled as local asset lookup misses or unverified entries.
   - Never surface network error dialogs or generic developer placeholders (`"word crude"`).
   - Fail closed:
     - Under `METADATA_RESOLUTION_FAILURE`: omit inline gloss; render `释义暂不可用` inside inspection surfaces without mutating underlying display decisions.
     - For `QUERY_DICTIONARY_NOT_CONTAINED`: zero styling, zero persistence; if explicitly queried, show `当前词典未收录`.
2. **Empty States:**
   - Empty Page: `No unfamiliar vocabulary detected on this page.`
   - Empty Notebook: `No matching words.`
   - Keep empty states quiet, muted, and centered without promotional graphics.

---

## 8. Host-Page Non-Interference & Technical Boundaries

1. **Selection & Navigation:**
   - Reading, selecting multiple sentences, copying text, clicking hyperlinks, and native scrolling must never be blocked, delayed, or hijacked.
2. **DOM Safety:**
   - Transparent extension wrappers may change DOM structure, but original text content, ordering, whitespace, punctuation, selection behavior and host-page semantics must remain preserved.
3. **CSS Isolation:**
   - All extension UI components (inspection popover, hover tooltip, recovery pill, popup) must use Shadow DOM encapsulation or rigorously prefixed BEM classes to guarantee immunity from host page stylesheet interference.
