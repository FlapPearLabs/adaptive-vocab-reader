## 4. Problem Statement

V0.1 已有可构建、真实 Chrome 验证过的 1,000 词垂直切片（阅读标注 + 50 题首测 + 持久化 + SPA），但产品未验收，且存在四个必须先解决的问题：

1. **状态身份错误**：当前实现以 surface stateKey 承载状态（`went` 与 `go` 状态分裂），与用户“认识一个词”的直觉和已确认的 wordKey 规则冲突。
2. **测试样本会被手动标记抹掉**：当前只有单槽 `WordState`，无 `AssessmentEvidence`；一旦实现估计，manual 覆盖将污染分子分母。
3. **估计与每日闭环缺失**：代码中没有任何估计展示（无 estimate/Wilson 相关实现）、没有每日五题生产闭环（无 daily 消息、无 DailyTestState）。
4. **审计入口仍可达**：popup 仍有「开始审计」按钮、恢复流程与首测建 marker 逻辑，worker 仍受理审计消息——与“冻结”不符。

## 5. 用户闭环

```text
阅读英文网页（wordKey 提示）
→ 50 题首测（写状态 + 写证据）
→ 看到单点估计 + 保守范围（只由证据派生，不外推）
→ 每天可选五题校准（补证据，估计收敛）
→ 手动 会/不会 随时改提示（不碰证据）
→ 刷新/重启持久化（schema 3）
→ 7 天 / 20 篇真人 dogfood → 用户明确接受/拒绝
```

---

## 6. Goals

1. wordKey 成为状态与证据的唯一身份键（`went/going/gone → go`；`could` 独立）。
2. 引入 `AssessmentEvidence`（每词最新一条），估计只由它派生。
3. 首测结果页展示单点估计 + 保守范围 + 不外推声明。
4. 每日五题校准轮（奇偶频段轮换、优先未测、可跳过/暂停/跨日过期）。
5. schema 2→3 一次纯迁移：surface key 合并 + 旧首测证据重建 + 审计数据清空。
6. 审计入口从 V0.1 用户路径彻底移除（代码冻结保留）。
7. 升级真浏览器 E2E 覆盖完整闭环；通过后进入人工 dogfood。

## 7. Non-goals

- 约 10,000 词扩容（dogfood 未被用户明确接受前不讨论）。
- 总体词汇量外推、CEFR、总体置信区间声明。
- 高置信自动隐藏、Pool B、PAV/Beta、隐藏词审计复活、复杂回填。
- SRS、遗忘曲线、到期队列、复习计划、通知、闹钟、调度器、自动 popup。
- Kaikki / OEWN / LLM 清洗 / 本地或云模型 / 上下文解释 / 全文翻译。
- 测试历史（事件溯源）、通用迁移框架、migration registry、3→2 降级。
- 日志、遥测、上报、dashboard；保存 URL/标题/正文/句子。
- 删除或重写冻结的审计代码；为冻结代码补测试。

## 8. 领域模型

术语定义见 [`CONTEXT.md`](../../CONTEXT.md)。本节给出施工级语义：

- **WordState**：某 wordKey 当前用于页面提示的 known/learning/unknown；最后一次显式动作（manual/initial/daily）生效；`WordStateSource` 增加 `daily`。
- **AssessmentEvidence（测试证据）**：某 wordKey 最近一次首测或每日测试结果：`outcome`（known/learning）、`source`（initial/daily）、`assessedAt`（作答时间，毫秒；0 表示旧版作答时间未知）。每词只保留最新一条；不是事件溯源或通用证据框架。
- **写入规则**：manual → 只写 WordState；initial/daily → 同时写 WordState 与 AssessmentEvidence。
- **读取规则**：内容脚本提示只读 WordState；估计、“是否已测过”、“最久未测”只读 AssessmentEvidence，禁止通过过滤 `WordState.source` 模拟。
- **DailyTestState**：最小持久化语义——`localDate`（创建计划时的本地日期）、`roundIndex`（创建时的 `completedRoundIndex`）、冻结的 5 道 `questions`、与 `questions` 等长的 `answers`、未答位置为 `null`、`completed`、`skipped`。状态约束：`completed=true` 仅当五题全部作答；`skipped=true` 只允许 `answers` 全为 `null`；用户从次级入口反悔开始时 `skipped` 变回 `false`、复用同一冻结计划；第一题作答后不得再变为 `skipped`；`completedRoundIndex` 只在 `completed` 首次变 `true` 时递增一次；不保存历史轮次、不建状态机框架或调度器。

## 9. wordKey 与词形行为

- canonical 规则：surfaceForm 小写后，若本身是 core 主词条 → wordKey=自身；否则 forms 映射到 core → wordKey=映射目标；未命中 → 非词典词。
- `could` 保持独立于 `can`（core 优先，13 个 forms 遮蔽 core key 的既有排除规则继续适用于首测候选自洽性）。
- 页面 `data-word`、存储键、测试候选键、证据键四者统一为 wordKey。
- 手动标记任一屈折形式，所有映射到同一 wordKey 的词形提示一致变化。

## 10. 首测

- 维持现有 50 题（十频段各五题）、四选一＋不确定、作答前冻结计划、确定性种子。
- 变更点：作答同时写 WordState（source=initial）与 AssessmentEvidence（source=initial, assessedAt=作答时刻）；**不再创建 AuditMarker**。
- 答对→known；答错或不确定→learning；未测词保持 unknown。
- 完成 50 题后结果页展示 §12/§13 的估计输出。

## 11. AssessmentEvidence

- 存储于快照新增字段（schema 3），键为 wordKey。
- 同一 wordKey 再次被测（每日）时整条覆盖为最新结果。
- manual 动作不创建、不修改、不删除证据。
- 证据不含题目内容、页面上下文或 URL。

## 12. 单点估计

- 每频段 b：`testedCount(b)` = 该频段有证据的不同 wordKey 数；`knownCount(b)` = 其中 outcome=known 的数量。
- `pointEstimate = round(Σ_b ((knownCount(b) / testedCount(b)) × bandWordCount(b)))`；正式估计只在首测完成后展示：十个频段每段必须至少一条有效 `AssessmentEvidence`；首测未完成或迁移损坏致任一频段零有效证据时，估计结果为 unavailable（UI 显示“完成或重新完成首测后可查看估计”），不把零样本频段按 0 掌握处理。
- 钳制到 `[0, 词包大小]`；词包大小是参数（当前 1000）。
- unsure 在证据中即 learning，计未掌握。

## 13. 保守范围

- 逐频段采用双侧 90% Wilson 区间（z = Φ⁻¹(0.95) ≈ 1.6448536269514722），按 `bandWordCount` 加权求和，四舍五入并钳制到 `[0, 词包大小]`。
- 必须满足 `low ≤ pointEstimate ≤ high`。
- UI 措辞只允许“保守范围”或“估计范围”；禁止“90% 置信区间”“总体覆盖率”等统计声称。
- 仅用于显示；不驱动自动隐藏、审计、Pool B、漏提示阈值或状态改写。
- 展示附带声明：「基于当前 1,000 词覆盖估计，不做外推」；不输出 CEFR。

## 14. 每日计划

- 每轮五题。频段选择：`completedRoundIndex` 为偶数 → 频段 0/2/4/6/8；奇数 → 1/3/5/7/9；每个选中频段一题。
- 只有完成整轮五题才递增 `completedRoundIndex`；两个已完成轮次覆盖十段。
- 选词（每个选中频段内）：优先没有 AssessmentEvidence 的 wordKey；同轮不重复；使用既有 install seed 与最小确定性排序；未测候选耗尽后选 `assessedAt` 最早的旧词。
- 题型复用首测的四选一＋不确定与冻结机制；作答双写 WordState（source=daily）+ AssessmentEvidence（source=daily）。
- 入口：用户主动打开 popup 才可见；无自动 popup、通知、闹钟、后台提醒或调度器；**首测未完成（`initialTest.completed≠true`）时，每日入口不可出现、不创建 `DailyTestState`**。

## 15. 跳过、暂停、跨日

- **跳过**：仅首题前可用；跳过 → WordState 与 AssessmentEvidence 零变化；跳过后主入口不再突出，保留次级“今天仍可开始”。
- **暂停**：回答第一题后隐藏跳过入口；同一本地日期内关闭 popup = 暂停，重新打开恢复同一冻结计划。
- **跨日**：本地日期变化 → 未完成轮次过期；已答题产生的 WordState/AssessmentEvidence 保留；未答题零变化；不回滚；不递增 `completedRoundIndex`；新一天按当前 `completedRoundIndex` 选频段；每个本地日期最多创建一轮。
- 本地日期通过最小可测试输入（date seam）传入纯函数；不建设时间服务。

## 16. schema 2→3 迁移

同一次纯函数迁移（并入现有 `migrateSnapshot`，不建通用框架），步骤：

1. **规范化旧 WordState key**：key 是 core → 保持；forms 映射到 core → 并入目标 wordKey；无法映射 → 保守保留原 key，不静默删除。
2. **冲突仲裁**（多 surface 并入同一 wordKey）：`updatedAt` 较新者胜出；完全相同时 manual 优先；仍相同时 learning 优先。
3. **重建旧测试证据**（CR-05 全部规则）：按相同下标配对 `initialTest.plan.questions` 与 `initialTest.answers`；只处理结构合法且 answer 非 null 的题；正确选项→known，错/unsure→learning；source=initial；assessedAt=0；不用 `Date.now`、不用 `snapshot.lastUpdated` 冒充、不从 `WordState.source` 反推；部分首测只恢复已答题；损坏、越界或无法配对的记录跳过；manual WordState 不被覆盖。
4. **审计冻结落地**：`auditMarkers` 清空；`auditPlan = null`；`auditLog` 保留但不转换为 AssessmentEvidence。
5. **数据安全**：迁移确定、纯函数、幂等；损坏输入不伪造数据；一次持久化写入；不提供原地 3→2 降级；dogfood 升级前保留旧快照副本。

**FormsMap 构建不变量**：所有 `forms` key 不得属于 core 主词条集合；所有 `forms` target 必须属于当前 core 主词条集合。因此 forms 中有映射 → 旧 surface key 并入 target wordKey；forms 中无映射 → 原 key 保守保留；`could` 等 core collision 不出现在 forms 中，故保持自身。现有构建测试与迁移集成测试必须验证这两个不变量，不新增 CoreSet、resolver 或通用映射层。

## 17. 审计冻结

- popup：移除「开始审计」入口、审计计划恢复流程与审计答题 UI。
- 首测作答不再创建 AuditMarker。
- worker 审计 handler、`strategy/audit.ts`、`worker/auditValidation.ts`、`shared/auditPlanVersion.ts`、相关类型与既有旧测试**暂时保留**：不删、不扩建、不加固；不新增对冻结 audit 算法/哈希/防篡改协议/候选池的测试，但允许为 V0.1 用户路径补最小回归测试（popup 无入口、不恢复 plan、首测不建 marker、schema 3 清空）。
- V0.1 任何用户可达路径不得调用审计模块。dogfood 后再决定是否删除。

## 18. 模块责任边界

只定义责任，不实现代码：

| 模块 | 责任 | 禁止 |
|---|---|---|
| dictionary/canonicalization | core 优先，把 surfaceForm 解析为 wordKey + 词典条目 + 频段 | 输出 surface stateKey |
| strategy（领域决策 seam） | 首测/每日选题、作答结算、估计（点值+范围）领域 interface | 读写 storage；被绕过；真浏览器 E2E 才是最高层验收 seam；worker/storage 集成测试是迁移与持久化 seam |
| storage migration | schema 3、surface key 合并、旧证据重建（纯函数） | 通用迁移框架、降级 |
| worker | 消息与持久化协调 | 不得加载完整词典或执行普通词典查询；仅允许在旧 schema 迁移时读取最小 `FormsMap` 并传给纯 `migrateSnapshot` |
| popup | 首测、估计展示、每日入口与进度 | 直连 quiz/audit 内部模块 |
| content | 只按 wordKey 的 WordState 决定提示 | 读取 AssessmentEvidence |
| E2E | 真实 Chrome 扩展交付路径 | 用纯函数调用冒充浏览器验证 |

禁止设计：通用 repository/service/controller 层、事件总线、调度器、migration registry、测试历史系统、新审计 facade、新完整性哈希、mock-only seam。

## 19. 失败模式与安全降级

| 失败 | 行为 |
|---|---|
| 迁移输入损坏（缺字段/越界/无法配对） | 跳过该记录，不伪造；其余正常迁移；不整体失败丢数据 |
| 估计分母为 0（任一频段零有效证据）或首测未完成 | 显示“完成首测后可见估计”，不显示 0 或 NaN；零样本频段不按 0 掌握 |
| 某频段候选词全部已测且证据齐全 | 按 assessedAt 最早回退选词 |
| 每日轮进行中扩展重启 | 冻结计划已持久化，同日恢复；跨日按 §15 过期 |
| 快照读出即为 v3 | 迁移幂等，恒等通过 |
| 未知 key 无法映射 | 保守保留，不参与估计（无证据），提示行为不变 |
| popup 在无词典数据时打开 | 显示加载失败，不写任何状态 |

## 21. 真浏览器 E2E（最高层验收 seam）

升级 `e2e-verify.cjs`，未来必须覆盖（当前未实现）：

1. 加载真实扩展构建产物；
2. 静态正文与 SPA 阅读标注；
3. 屈折词形共享 wordKey（标记 went，going 同步变化）；
4. 完成 50 题首测；
5. 结果页显示点估计＋保守范围＋不外推声明；
6. manual 改提示但估计不变；
7. 首测未完成时，popup 不显示每日入口，storage 中不创建 `DailyTestState`；完成首测后每日入口才出现；
8. 完成每日五题；
9. 每日答案更新状态与估计；
10. 首题前跳过零变化；
11. 同日关闭/重开 popup 暂停恢复；
12. 模拟本地日期变化（date seam 最小注入）；
13. 跨日已答保留、未答过期；
14. 注入真实 schema 2 fixture，经实际 worker/storage 路径升级到 v3；
15. 刷新与浏览器重启后持久化；
16. popup 无审计入口；
17. 阅读不被每日测试阻塞。

约束：不得只调用迁移纯函数就声称浏览器迁移通过（场景 14 必须走真实扩展存储路径）；date seam 只允许最小可测试输入，不建时间服务。

持久化验收补全：浏览器重启后必须同时验证 `WordState`、`AssessmentEvidence`、`DailyTestState`、`completedRoundIndex`、`schemaVersion=3`；两个真实标签页包含同一 `wordKey` 不同词形时，manual 或 daily 状态更新后两标签页同步；迁移 E2E 由真实 schema 2 fixture 走 worker/storage 路径锁定（场景 14 不只调纯函数冒充浏览器迁移）。

## 22. 人工 dogfood

- 门槛（固定值）：连续 7 天；每天至少实际使用插件阅读一篇真实英文网页；累计至少 20 篇。
- 每篇最多人工抽查 20 个相关词，分别记录三个独立数字：**不必要提示**、**释义不可用**、**覆盖缺失**（定义见 `CONTEXT.md`）。
- 同时记录：当天日期、当天阅读篇数、状态/进度是否丢失、估计是否看得懂且有用；人工验收 seam 只由用户签字/确认，不伪装成自动 E2E。
- 不保存 URL、页面标题、正文、句子；不建设日志、遥测、上报或 dashboard。
- 最终由用户明确接受/拒绝；未明确接受不得讨论 10,000 词扩容。

## 23. 反过度设计门禁

每个实现 ticket 必须通过以下检查，否则不予验收：

1. AssessmentEvidence 只为避免 manual 覆盖测试样本；每词一条，不存历史，不做事件溯源。
2. schema 3 是一次必要迁移；不建迁移框架、registry 或降级路径。
3. DailyTestState 只承载当前一天的一轮五题；不建调度器、队列或提醒。
4. Wilson 只用于显示；不恢复概率画像、不驱动任何自动行为。
5. 不扩建 audit；为当前 V0.1 用户路径补最小回归测试（R-AUD-1~3 已定义）而非为冻结代码补测试；不新增对冻结 audit 算法/哈希/防篡改协议/候选池的测试。
6. 不引入通用 repository/service/controller、事件总线、mock-only seam。
7. 每项 ticket 必须对应用户可见行为或必要数据安全风险，并回答“用户现在多得到了什么”。
