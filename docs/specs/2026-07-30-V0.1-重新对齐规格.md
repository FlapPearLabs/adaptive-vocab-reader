- **状态**：草稿，待用户与 Codex 审批。未批准前不得进入实现。
- **生成日期**：2026-07-30
- **唯一产品规则来源**：[`RULES.md`](../RULES.md)（其 `[已确认]` 条目为本规格的权威输入）
- **领域语言**：[`CONTEXT.md`](../CONTEXT.md)
- **取代关系**：`docs/specs/2026-07-22-*` 三份旧规格（范围重置 / 1000词垂直切片 / 掌握预测与主动校准）**自本规格批准起被取代**，仅保留为历史施工证据，**不再作为新增实现的授权**。旧 GitHub `#1–#5` 同样仅作历史证据。
- **本轮纪律**：保护 dirty worktree；不 commit / push / merge / deploy；不修改生产代码（除本规格与 RULES/CONTEXT 的治理更新外）；不发布 GitHub、不改旧 Issue。

## 1. Problem Statement

V0.1 当前已有一个可构建、可用真实 Chrome 验证的 ~1,000 词本地垂直切片（正文阅读标注 + 50 题首测 + 持久化 + SPA 支持），但**产品尚未验收**：

1. 首测结束后**没有把结果转成用户可理解的词汇量估计**（单点值 + 范围都没有真实展示）。
2. **简单每日更新测试未落地**——代码里只有「可选每日更新」的占位，没有真实的 5 题/天、按频段抽样、可跳过、改写状态的闭环。
3. 现有代码严重**过度设计**：一整套「隐藏词审计 / Pool B / Wilson / PAV-Beta / 高置信自动隐藏 / 防篡改哈希」机制对应被 RULES 推迟的功能，当前零用户闭环驱动，却占了大量 diff 与维护面。
4. 旧 2026-07-22 规格写「V0.1 必须具备 ~10,000 词」「掌握预测与主动校准」等范围，已被 RULES 明确推翻，但仍在误导实现授权。

本规格把 V0.1 收敛到**单一可演示用户闭环**：读英文网页 → 50 题首测 → 看到真实词汇量估计 → 每天 5 题可选更新让估计收敛 → 持久化 → 真人 dogfood 验收。

---

## 2. Solution

在**不扩建、不删除**现有超范围代码的前提下，补齐 V0.1 真正缺的两块用户行为：

- **(A) 首测结果 → 词汇量估计展示**：50 题结束后，结果页渲染「单点估计值 + 保守范围」，明确标注「基于当前 1,000 词覆盖估计，不做外推」。估计算法按十频段聚合，单词状态为单一真相源。
- **(B) 简单每日更新**：默认 5 题/天，从 1,000 词包按十频段比例抽样，用户可随时跳过；每日答案改写 `wordKey` 状态并触发估计实时重算。

两者都**命中真实交付路径**，不引入新协议、新抽象或迁移层。所有被推迟的复杂机制标记为「保留但冻结」（见 §8 处理表）。

## 3. User Stories

- **US-1 阅读标注**：作为 dogfood 用户，打开英文网页时生词被标注（不会=强提示，未知=轻提示），以便边读边学，且同一页面不重复打扰。
- **US-2 首测估计**：作为新用户，完成 50 题首测后立刻看到「约掌握 X/1000 核心词」的单点值 + 一个保守范围，并被告知这是基于当前 1,000 词包的估计、不外推。
- **US-3 每日更新**：作为用户，每天可花约 1 分钟做 5 道可选更新题（按十频段抽样），随时可跳过且不影响阅读；作答后我的词汇量估计悄悄变得更准。
- **US-4 持久化**：作为长期用户，刷新或重开浏览器后我的 `wordKey` 状态与每日进度都还在，不丢失。
- **US-5 不误导**：作为用户，词汇量估计简单易懂（单点+范围），不会被暗示成「你的总体词汇量」或「CEFR 等级」。

## 4. Implementation Decisions

> 以下 ID-1…ID-7 均已在 `/grill-with-docs` 阶段由用户逐题明确确认为 A，并同步写入 `RULES.md`。

- **ID-1 估计展示形式**：首测结果页**同时展示单点估计值 + 保守范围**，标注「基于当前 1,000 词覆盖估计，不做外推」。（来源：RULES「词汇量估计」条）
- **ID-2 估计含义**：估计**只针对当前 1,000 词包内的掌握量**，不外推到更大规模、不输出 CEFR 等外推量级；算法按十频段聚合、词包大小作为参数，未来扩容可复用但 V0.1 不实现。
- **ID-3 每日更新参数**：默认 **5 题/天**，从 1,000 词包**按十频段比例抽样**（首测 50 题迷你版），**不引入新词**；**可随时跳过**，跳过当天不更新、无惩罚、不阻塞阅读。
- **ID-4 每日→状态/估计机制**：每日答案**改写 `wordKey` 自身持久状态**（答对→升会/确认会；答错→降不会）；**十频段估计实时从频段内所有 `wordKey` 聚合状态重算**；跳过=无变化；`wordKey` 状态为唯一真相源。
- **ID-5 超范围代码姿态**：现有复杂审计代码（`strategy/audit.ts`、`worker/auditValidation.ts`、`shared/auditPlanVersion.ts`、`AuditMarker`/`AuditPlan`/状态版本）及 2026-07-30 close-out 加的 FNV-1a 哈希 + worker fake-strategy seam 测试，**保留但冻结**——不删、不扩建、不被任何 V0.1 用户路径调用。
- **ID-6 dogfood 完成标准**（扩容与 V0.1 验收门槛）：连续使用 ≥ 7 天且每天实际阅读；累计阅读真实英文网页 ≥ 20 篇；误提示率可接受（本地日志判定、无系统性误标）；词典缺失可容忍且不阻断阅读；刷新/重开浏览器后状态与进度无丢失；词汇量估计用户本人可读懂且觉得有用（口头确认）。数字为建议值，可由用户调整。
- **ID-7 最高层测试 seam**：真浏览器 E2E（`e2e-verify.cjs` + Chrome for Testing）为最高层验收 seam，升级为覆盖「首测结果展示 + 每日更新 + 持久化」完整闭环；真人 dogfood 门槛为叠加人工验收门，不替代 E2E。

## 5. Testing Decisions

- **TD-1 最高层 seam = 真浏览器 E2E**：升级现有 `e2e-verify.cjs` 三阶段为完整闭环——装插件 → 打开英文页标注生词 → 弹窗做 50 题 → **断言结果页含单点值+范围** → 做/跳每日 5 题 → **刷新后断言 `wordKey` 状态与每日进度持久化**。不依赖被冻结的 audit seam。
- **TD-2 估计聚合单测/策略测试**：用 `createVocabStrategy()` 的纯函数层断言「估计只聚合当前词包内 `wordKey` 状态、按十频段加权、不外推」。命中真实交付路径，不补 mock。
- **TD-3 不新增审计测试**：冻结代码不补新测试 seam；现有 audit/test seam 保持冻结，不继续加固（呼应 RULES「拒绝局部过度设计」）。
- **TD-4 验收映射**：任何「测试全绿」都必须能映射到 RULES 的已批准用户闭环（阅读→首测→估计→每日→持久化），代理自述不构成验收。

## 6. Out of Scope（明确不做）

- ❌ 扩容到 ~10,000 词（必须等 ID-6 dogfood 完成后再决定）。
- ❌ Kaikki / OEWN / LLM 清洗 / 本地模型 / 云模型 / 上下文解释（RULES「明确不做」）。
- ❌ 高置信自动隐藏、隐藏词审计、Pool B、Wilson 区间、PAV/Beta 后验、复杂三桶配额、受控回填。
- ❌ 词汇量估计外推（CEFR / 总体词汇量证书）。
- ❌ 删除或大规模重写现有超范围代码（本轮只冻结，见 §8）。
- ❌ 新增协议、抽象、迁移层或额外测试 seam（除非当前用户闭环明确需要）。

---

## 7. Further Notes

- **未来扩容复用点**：估计的「按十频段聚合、词包大小作为参数」形态，使 1,000→10,000 扩容时无需重写算法，仅需换词包与重新校准频段边界。这是 ID-2 的设计约束，不是 V0.1 功能。
- **dogfood 是验收门不是功能**：ID-6 的门槛用于决定是否进入扩容/复杂审计讨论，本身不增加任何代码。
- **冻结代码的复活条件**：仅当 dogfood 真跑出需要审计/隐藏/Pool B 的证据时，才在**新一轮 Spec** 中把对应项从「保留但冻结」移入「简化」或「启用」，且必须有具体验收场景驱动。

---

## 8. 拒绝局部过度设计（验收门）

每项 V0.1 实现必须通过以下四条，否则视为过度设计、不予验收：

1. **每项实现必须带来可演示的用户行为**——能回答「用户现在多得到了什么」。
2. **测试优先命中真实交付路径**——E2E/策略层测试覆盖真实阅读→首测→估计→每日→持久化，不为覆盖率补 mock。
3. **不因为现有架构已经复杂就继续补全复杂架构**——冻结的 audit/哈希/状态版本代码不因「还能更完整」而被激活或扩建。
4. **不因未来可能需要而提前增加协议、抽象或迁移**——新抽象/审计层/统计模型必须由当前 Spec 的具体验收场景驱动。

## 10. Requirement → Behavior → Test Seam 映射

### 10.1 词汇量估计

| Requirement | Behavior（用户可见） | Test Seam |
|---|---|---|
| R-EST-1 首测后展示单点值+范围，不外推（ID-1） | 结果页渲染「约掌握 X/1000 核心词」+「约 [low]–[high]」并标注「基于当前 1,000 词覆盖估计」 | E2E 断言结果页 DOM 含单点值与范围文本 |
| R-EST-2 估计只含当前 1,000 词包（ID-2） | 估计函数输入=当前词包 `wordKey` 状态集合；无外推输出 | 策略层单测断言估计只聚合当前词包、无 CEFR 字段 |
| R-EST-3 按十频段聚合、可扩展（ID-2） | 估计 = Σ(各频段掌握比例 × 频段词数)；词包大小作为参数 | 策略层单测断言频段加权正确、换词包不需改算法 |

### 10.2 简单每日更新

| Requirement | Behavior（用户可见） | Test Seam |
|---|---|---|
| R-DLY-1 默认 5 题/天、按频段抽样、1k 包内、可跳过（ID-3） | 每日弹窗 5 题，来源=1k 包按十频段比例；显式「跳过」按钮；跳过不阻塞阅读 | E2E 断言每日 5 题出现 + 可跳过 + 阅读流未中断 |
| R-DLY-2 每日答案改写 `wordKey` 状态、估计实时重算（ID-4） | 答对→升会/确认会；答错→降不会；刷新后状态在；估计值随之变化 | E2E 断言刷新后状态持久化 + 估计值相对首测变化 |
| R-DLY-3 跳过=无变化（ID-3/4） | 点击跳过当天不写任何状态、估计不变 | E2E 断言跳过后 `wordKey` 状态与估计与跳前一致 |

## 11. 批准与后续
