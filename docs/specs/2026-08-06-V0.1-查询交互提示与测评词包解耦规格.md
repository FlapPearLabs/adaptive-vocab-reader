## 2. BACKGROUND

本轮依据 2026-08-06 只读架构调查 [`outputs/2026-08-06-architecture-coupling-investigation.md`](../../outputs/2026-08-06-architecture-coupling-investigation.md)（复现包见 `work/investigations/2026-08-06-architecture-coupling/`）与用户最新产品目标修订文档。

调查确认的十个关键事实：

1. 当前运行时查询范围只有 1,000 个 core wordKey 和 1,505 个有效 forms alias；指定 14 个样本中 7 个完全未命中，且对应 lemma 也不在 core。
2. `dictionary.lookup` 返回 null 的词在进入状态与展示策略前即被跳过，没有任何查询或反馈入口。
3. 成功 lookup 但 `decision=none` 的词不生成 `.avr-word`，因此没有 hover tooltip 或会/不会菜单。
4. 当前无显式状态一律解释为 unknown，unknown 无条件产生 light 灰线；首测只固定改 50 个词，剩余 950/1000 仍为 unknown，所以「词包内绝大多数词满篇灰线」是当前规则的天然结果。
5. 当前没有真正的「潜在可能不会」概率、能力阈值、频率阈值或候选稀疏化逻辑。
6. 查询能力、交互能力和是否显示灰线被 `.avr-word` 包装结构耦合：只有 `lookup != null && decision != none` 才生成包装，tooltip 和菜单只作用于 `.avr-word`。
7. 查询词典、首测词包、每日校准、AssessmentEvidence 和词汇量估计目前共用固定 1,000 core 范围。
8. tooltip 当前以目标词左上角为锚点、`top=y-8` 且只处理 bottom/right 溢出，会覆盖目标词和相邻正文，顶部附近还侵入 sticky header。
9. 真实鼠标拖选会发生 `mouseup → action inserted → click → action removed`，导致「加入生词本」按钮在真实手势中被同一手势的后续 click 立即隐藏；现有 E2E 只合成 `Range + mouseup`，不包含后续 click。
10. 当前生产代码基本忠实实现了旧 RULES/Spec；本轮问题属于产品目标变化和规则漂移，不能简单归咎为 Codex 未按旧规格实现。

**为什么仅扩词典或仅补 forms 不能解决问题**：

- 扩大词典只能改善 lookup-null（事实 1、2）；不能解决 known/无视觉提示词的交互（事实 3），不能解决灰线密度（事实 4、5）。
- 仅补 forms 只能修复 lemma 已在 core 的屈折漏映射；本组 7 个缺失词对应 lemma 均不在 core（事实 1），因此补 forms 对它们无效。
- 反过来，如果先实现提示稀疏化但仍只包装提示词，会让更多可查询词失去 hover/click（事实 6）。
- tooltip 遮挡（事实 8）与真实拖选（事实 9）是独立的实现/测试 seam 差距，与词典规模无关。

**规则与目标漂移定性**：当前代码忠实执行旧规则（unknown=light、known=不提示、固定 1,000 词同时承担查询/测评/估计），但旧规则已与本轮最新产品目标冲突。本规格的任务是把新目标写成无冲突、可验收的产品合同，记录 A–F 决议（E/F 为条件决议）与公开再分发边界（D 的最终实现选择已批准、E 公开再分发验证结果 UNKNOWN）。

## 3. GOALS

下列 GOAL 1–7 为**用户已确认但尚未实现**的高层产品方向。**OPEN_DECISIONS A–F 已由用户于 2026-08-06 逐项决议**（§14）：A=dogfood 驱动覆盖验收、B=未收录仅提示不进生词本、E=ECDICT 全量本地（**条件决议，已验证通过限定本地范围**）、F=包外词同键不区分来源不升 schema（**条件决议，前提同 E，已随 E 生效**）、D=开发前可丢弃原型对比透明包装与 caret 定位（**原型已完成；已批准生产实施路线＝透明 span 包装 + 事件委托，caret 不作唯一交互基础**）、C=dogfood 密度参考+不必要提示人工验收（**输入/算法/bootstrap 已对齐：仅频率+状态过滤、频率下界阈值、首轮＝有效频率 rank 中间索引阈值（index ⌊n/2⌋，0-based）**）。已决议 ≠ 已实现；E 验证范围限定个人本地 dogfood、不公开发布，公开再分发仍 UNKNOWN；候选提示输入/算法已对齐，D 最终实现选择已于第二道 DOCUMENT 审查后由用户批准（2026-08-07）。

1. **广查询能力**：普通英文网页中的普通英文词，原则上都应能够查询词义，看到原词或词形、音标、词性和中文释义。
2. **无提示词仍可交互**：无灰线词（含系统判断应该会的词、known 词）仍可悬停查询、点击反馈“不会”。
3. **稀疏灰线**：灰色虚线只用于系统判断为「用户潜在可能不会」的少量候选词；未测试词不得无条件成为灰线候选。
4. **用户纠错闭环**：用户明确反馈“不会”进入生词本并显示红色强提示；反馈“会”后红色提示和生词本条目消失，但该词仍可查询、可再次纠错。
5. **查询与测评分离**：查询词典负责网页查词、词形解析、释义、会/不会反馈和生词本；固定测评词包负责首测、每日校准、frequency band、AssessmentEvidence 和词汇量估计；测评包外查询词不进入 Evidence、不参与估计。
6. **tooltip 不遮挡**：tooltip 尽量不遮挡目标词和正文，优先上方、必要时下方，不超出视口，不侵入 sticky/header 安全区域，滚动后定位仍正确。
7. **真实鼠标路径**：真实 mouse down/move/up 拖选成为可验收路径，不再只用合成 `Range + mouseup` 代替真人拖选。

- **不选择在线服务**：不选择联网词典、远程 API、服务端查询、云端画像或遥测；本规格不授权引入任何远程组件（见 §11）。
- **不预设已批准路线之外的实现结构**：D 的生产路线已经批准＝**透明 span 包装 + 事件委托**，caret 不作为唯一交互基础；本 Spec 不预设的是该已批准路线内部更低层、未经确认的实现细节（具体内部实现由后续 ticket 在本 Spec 约束下确定），而不是路线本身；不得重新把 D 写成待选路线。
- **不设计本地模型**：不设计本地 LLM、模型推理、概率画像或能力模型；不恢复 Kaikki/OEWN/COW/LLM 清洗路线。
- **不开始开发**：本规格是文档阶段产物，不生成或拆分开发 ticket，不标记 ready-for-agent，不写测试代码。
- **不重做词汇量估计算法**：单点估计与 Wilson 保守范围语义保持不变；仅新增「包外词不进入估计」的边界（R-ASSESS-3）。
- **不上传页面内容**：不上传用户网页正文、浏览历史；不新增日志、遥测、上报或 dashboard。
- **不保证任意字符串都有词典释义**：不把“所有英文字符串、代码、URL、专有名词、缩写”无边界地解释为必须查词（A 决议：不设语料阈值，覆盖验收由 dogfood「覆盖缺失」驱动）。

## 5. DEFINITIONS

与 `CONTEXT.md` 保持一致，并补充本轮需要的区分：

- **surface form（页面词形）**：用户在网页中实际看到的字面形式，保留原文大小写，用于定位页面位置与 tooltip 首行展示；它不是独立的状态或证据单位。
- **assessment wordKey（当前测评身份键，已确认事实）**：当前 main 实现与固定测评包中，个人词汇状态、测试证据、取义和频段的唯一身份单位，即 ECDICT core 主词条的小写形式；纯屈折变化的页面词形共享映射目标的词汇键，页面词形本身若是主词条则优先使用自身（core 优先）。
- **query canonical identity（查询身份模型，已生效）**：未来查询词典中用于标识与同步「同一词」的身份模型。**OPEN_DECISIONS E/F 已决议并生效（限定本地范围）**：查询词典方向为 ECDICT 全量本地（E 验证通过：MIT 正面授权个人本地使用与打包，不公开发布），包外词沿用与包内相同的字符串身份键、不区分来源、不升级 schema，身份即「查询词典（ECDICT 体系）定义的 lemma」。**范围限定：仅个人本地 dogfood 与本地打包（load unpacked）；对外公开再分发不在生效范围，权利链仍 UNKNOWN，若需公开则 E/F 返回用户重新决策（fail-closed，§14 E、§18）。**
- **query dictionary（查询词典）**：负责网页查词、词形解析、释义展示、会/不会反馈和生词本元数据的词典来源。**当前实现中即固定 1,000 core + forms（对应 assessment wordKey 身份）**；**OPEN_DECISIONS E 已验证通过（限定本地范围）**：方向为 ECDICT 全量本地词典。**query eligibility 只依赖身份+展示元数据（音标/词性/中文释义），不要求频率**——只读实测 query-eligible 词 **121,340** 条（原始 CSV 770,611 行 / 65.9 MB；裁剪后按现有 121 B/词条估算约 14.7 MB，最终以实施口径实测为准）；具体条目数由数据可行性决定、不预设，不公开发布。
- **assessment vocabulary（固定测评词包）**：负责首测 50 题、每日校准五题、frequency band、AssessmentEvidence 与词汇量估计的词包。当前即固定 1,000 词包；扩容冻结。
- **explicit user state（用户显式状态）**：用户通过手动标记、首测作答、每日作答写入 `WordState` 的 known / learning（或尚无可查记录的 unknown 语义）。unknown 只表示“尚无显式反馈”，不等于“潜在不会”。
- **hint candidate（主动提示候选）**：系统判断为「用户潜在可能不会」并因此显示灰线的词。它是独立于用户显式状态的预测维度，不写入用户状态。**C 已对齐输入/算法/bootstrap**：候选输入＝查询词典频率（frq/bnc）+ 用户显式状态过滤（排除 known/learning 词），不含 AssessmentEvidence/band；算法＝频率下界阈值——**首轮中间索引阈值 T₀ = S[⌊n/2⌋]（S＝有效 effectiveFrequencyRank 升序列表，n=|S|，0-based；偶数 n 时取两个中间元素中的上侧元素）**；light 候选判定方向与边界：`effectiveFrequencyRank > T₀`（严格大于，等于不提示）；frq/bnc 均无效时 hint-ineligible 但仍 queryable；随后由 dogfood 密度数据校准分位点。**无有效频率排名的可查询词不参与候选判定，但仍可查询、可反馈（query eligibility 独立于 hint eligibility）**。
- **light hint（轻提示/灰线）**：候选词的浅灰虚线样式；按新目标只用于少量潜在不会候选。
- **strong hint（强提示/红色）**：用户明确反馈“不会”（learning）的词的红线下划线（同页首次含行内中文）。
- **queryable（可查询）**：一个词在页面上能够被悬停查询释义、被点击反馈会/不会。可查询与是否显示灰线无关。
- **query-entry eligibility（查询资格，与 hint eligibility 独立）**：决定一个词是否进入查询词典、能否被查询。**只依赖查询所需身份（canonical lemma 或词形映射）与展示元数据（音标、词性、中文释义），与 frq/bnc 是否存在无关**。只读实测（2026-08-07，见研究 §2.3）：ASCII 小写单词+音标+词性+中文释义的 query-eligible 词 **121,340** 条。**缺 frq/bnc ≠ 不可查询，也不得把缺频率词变成 lookup-unresolved。** 当前 RULES 的「缺 frequency rank 淘汰」仅属于固定 1,000 测评包/旧高频构建规则，不得默认套用到查询词典。
- **hint eligibility（提示候选资格，与 query eligibility 独立）**：决定一个词能否作为主动提示候选（显示灰线）。**C 已对齐输入：仅查询词典频率（frq/bnc）+ 用户显式状态过滤（排除 known/learning），不含 Evidence/band；算法＝频率下界阈值**。因此**无有效 frq/bnc 排名的可查询词（实测 81,250 条）不具备提示候选输入，不参与灰线候选判定，但仍保持可查询、可反馈**——不因缺频率失去查询资格（见 §8 职责表与 §9 AC-7）。
- **effectiveFrequencyRank（有效频率排名，最小只读频率元数据）**：查询词典为 Hint selection 提供的只读频率元数据。组合/回退规则沿用已确认口径：**`frq` 有效排名优先，`frq` 缺失时用 `bnc` 有效排名**；两者均无效时该词 **hint-ineligible**（但 query eligibility 不受影响）。比较方向：**`effectiveFrequencyRank > 当前阈值` 才可能成为 light 候选**（rank 越大＝越生僻）。它**不是 AssessmentEvidence、不是 frequency band**，不进入估计、不改变 WordState；本定义只规定数据合同，不指定 JSON sidecar、字段布局、数据库或新 schema。
- **lookup unresolved（查询未解析）**：`dictionary.lookup(surfaceForm)` 返回 null（lemma 不在查询词典，或词形映射缺失）。当前实现中此类词无任何入口；目标行为已决议（OPEN_DECISIONS B：仅提示「当前词典未收录」，不进生词本；AC-10 入口界定见 §9）。**注意：缺频率不是 lookup unresolved 的原因。**

## 6. PRODUCT_INVARIANTS

以下不变量属于**已确认但尚未实现**的产品方向，在本轮用户目标下成立，任何后续 Spec/ticket 不得违背；「少量」候选的验收方式已决议（OPEN_DECISIONS C：dogfood 密度参考 + 不必要提示人工验收），候选输入/算法已对齐（仅频率+状态过滤、频率下界阈值，**首轮阈值＝有效频率 rank 中间索引阈值（index ⌊n/2⌋，0-based）**、dogfood 校准分位点），实现须经后续 ticket 阶段与用户“开始开发”授权。

- **可查询与是否提示分离**：是否能够查询和反馈，不得由是否显示灰线决定。
- **用户状态与预测候选分离**：未显式反馈 ≠ “不会”；系统预测“可能不会” ≠ 用户已明确标记 learning；候选判断不得无条件改写用户明确状态。
- **known 可查询、可纠错**：known 只代表用户当前明确认为自己会；不显示学习提示，但仍可查询，仍可重新反馈“不会”。
- **learning 红色并进入生词本**：用户明确反馈“不会”后，同一身份键（E/F 已生效：ECDICT lemma 字符串键，包外词同键；生效范围＝E 验证的本地范围）的相关页面实例同步显示红色强提示并进入生词本。
- **包外词不影响 Evidence/估计**：查询词典内、固定测评包外的词即使持有 `WordState` 或进入生词本，也不写入 `AssessmentEvidence`、不参与词汇量估计。
- **不静默把系统预测写成用户明确状态**：系统预测不得创建或改写用户显式状态记录。
- **灰线必须稀疏**：灰线只用于系统判断为“用户潜在可能不会”的少量候选，而不是所有未测命中词。
- **local-first**：不上传网页正文、浏览历史；不新增远程查词、云端画像或遥测。

## 7. USER FLOWS

以下流程是待实现的产品行为描述。完整解耦目标当前未实现；各条已标注「当前已实现 / 部分 / 差距」以区分已有行为与目标差距，标注仅供对照，不代表新目标已达成。

- **A. 系统认为可能不会且显示灰线**：页面普通词被候选策略判定为“潜在可能不会”→ 显示浅灰虚线；悬停显示 词形/音标/词性/释义；点击弹出会/不会菜单；反馈“不会”→ 红色强提示 + 生词本；反馈“会”→ 灰线消失但仍可查询。当前实现中所有未测命中词无条件灰线，无候选策略（差距）。
- **B. 系统认为应该会、无灰线，但用户悬停查询**：无灰线词仍可悬停显示完整 tooltip；tooltip 不遮挡目标词和正文。当前实现中无灰线词（none）无包装、无 hover（差距）。
- **C. 无灰线词被用户标记不会**：点击无灰线词 → 反馈“不会”→ 进入生词本并显示红色提示。当前实现中无包装词不可点击（差距）。
- **D. learning 词被标记已掌握**：点击“已掌握”（或点击菜单“会”）→ 红色提示消失、生词本条目消失；该词仍可查询、可再次标记不会。当前实现支持状态切换（已实现），但“仍可查询”需要无包装交互支持（部分差距）。
- **E. known 词重新标记不会**：known 词无学习提示，但用户可再次点击反馈“不会”→ 重新进入生词本并显示红色。当前实现中 known 词无交互载体（差距）。
- **F. 屈折词形映射到身份键**：页面 `abilities` → wordKey `ability`；标记任一词形，同 wordKey 所有词形同步。当前已实现（R-KEY 系列，基于 assessment wordKey；E/F 条件决议查询身份为 ECDICT lemma 同键体系，前提＝E 许可证/数据可行性验证通过）。
- **G. 查询词典内但测评包外的词**：可查询、可反馈、可进生词本；不产生 AssessmentEvidence；不改变估计。当前查询词典与测评包同范围，无“包外但在查询词典内”的词存在（差距）。
- **H. lookup 无法解析的普通英文 token**：用户悬停/点击时至少有明确的“当前词典未收录”响应（B 已决议：仅提示，不进生词本），不得表现为插件毫无反应。当前实现中此类词无任何入口（差距）。
- **I. tooltip 位于普通、顶部、底部、左右边界和 sticky header 附近**：分别验证上方优先、下方翻转、不超出左右视口、不侵入 sticky/header 安全区域。当前实现只处理 bottom/right 溢出，覆盖目标词和正文（差距）。
- **J. 真实鼠标拖选辅助入口**：真实 mouse down/move/up 产生选区后弹出「加入生词本」；同一手势的后续 click 不得提前隐藏入口；点击后写入 learning。当前真实拖选存在 `mouseup → insert → click → remove` 竞态（差距）。
- **K. 页面动态更新后的查询与提示**：SPA 动态插入的正文、字符级更新（characterData）后，可查询词与提示保持一致。当前 observer 不监听 characterData，部分动态文本在快照时尚未重新包装（部分差距，见调查 §6）。

## 8. QUERY / STATE / HINT / ASSESSMENT RESPONSIBILITIES

四层职责表（只定义责任与边界，不指定实现）：

| 维度 | Query layer（查询层） | User state layer（用户状态层） | Hint selection layer（提示候选层） | Assessment and estimation layer（测评与估计层） |
|---|---|---|---|---|
| 输入 | surface form + 查询词典（E 已验证：ECDICT 全量本地方向；**query eligibility 只依赖身份+展示元数据，不要求 frq/bnc**，条目数由数据可行性决定） | 用户显式动作（manual/initial/daily） | 查询结果 + 用户显式状态 + **effectiveFrequencyRank（frq 优先、bnc fallback；双缺失＝hint-ineligible），不含 Evidence/band（C 已对齐）**；**hint-ineligible 的可查询词不参与候选判定，但保留查询资格** | 固定测评词包 + AssessmentEvidence |
| 输出 | 身份键（E/F 已生效：ECDICT lemma 字符串键，包外词同键、不区分来源）+ 条目（音标/词性/释义） | WordState：known / learning / 无记录 | light hint 或 无提示（频率下界阈值，首轮 T₀＝有效频率 rank 中间索引阈值 index ⌊n/2⌋ 0-based、dogfood 校准分位点；D 已批准生产实施路线＝透明 span 包装 + 事件委托） | 首测/每日题目、单点估计 + Wilson 保守范围 |
| 持久化与否 | 不持久化（查询词典是静态资产） | 持久化（WordState） | 不持久化（预测是派生展示，不落盘） | 持久化（AssessmentEvidence、DailyTestState 等） |
| 是否影响生词本 | 提供元数据（可查词才有释义可展示） | 是：learning 进入、known 移出 | 否：候选不直接进生词本，只有用户反馈才进 | 否：证据不决定生词本（活跃生词表是确认不会清单） |
| 是否影响估计 | 否 | 否（manual 不进入估计） | 否 | 是：估计只读测评包内 Evidence |
| 禁止承担 | 不得改写状态、不得写证据、不得决定灰线 | 不得创建/改写 AssessmentEvidence；不得把“预测”写成显式状态 | 不得改写用户显式状态、不得把预测落盘、不得直接决定测评 | 不得读取/改写用户页面状态来凑估计；包外词不得进入 |

补充职责边界（与旧 Spec §18 一致性）：

- **dictionary/canonicalization**：**当前 main 实现事实**——`surface → 身份键（assessment wordKey）+ 条目 + 频段`（固定 1,000 core/forms 范围）。**目标合同（取代旧口径，见 §5/§8 职责表）**——`surface → query canonical identity + query entry`（query eligibility 只依赖身份+展示元数据，不输出频段、不依赖 assessment band 作为查询资格或普通查询输出）；**Hint selection 单独消费 `effectiveFrequencyRank`**；**frequency band 只归固定 assessment vocabulary / Assessment layer**，用于测试与估计；不输出 surface stateKey；不决定展示。
- **strategy（领域决策 seam）**：展示决策拆为「显式状态提示」与「候选提示」两个独立输出；**C 输入/算法已对齐（2026-08-07）**——候选输入＝仅 `effectiveFrequencyRank`（frq 优先、bnc fallback；双缺失＝hint-ineligible）+ 用户显式状态过滤（排除 known/learning），不含 Evidence/band；算法＝频率下界阈值（**首轮中间索引阈值 T₀ = S[⌊n/2⌋]（0-based；偶数 n 时取两个中间元素中的上侧元素）；light 方向与边界：`effectiveFrequencyRank > T₀`（严格大于，等于不提示）；随后 dogfood 校准分位点**）。**D 已批准生产实施路线＝透明 span 包装 + 事件委托（2026-08-07，prototype 仅为设计证据）；生产实现仍须经后续 ticket 阶段与用户“开始开发”授权。**
- **content**：只消费查询层与展示决策输出；不读取 AssessmentEvidence。
- **worker**：不得加载完整查询词典或执行普通词典查询（迁移时仅读取最小 FormsMap 除外）。
- **popup**：生词本、首测、每日、估计入口职责不变；估计仍只读证据。
- **禁止设计**（沿用旧 Spec §18）：通用 repository/service/controller 层、事件总线、调度器、migration registry、测试历史系统、新审计 facade、新完整性哈希、mock-only seam。

## 9. ACCEPTANCE CONTRACT

只写行为验收，不指定实现技术。以下每条均为待实现的验收项（当前均未满足，除非注明）：

- **AC-1**：一个无灰线但可查询的词能显示完整 tooltip（词形/音标/词性/释义四行），tooltip 不遮挡目标词与相邻正文。
- **AC-2**：无灰线词可通过点击反馈“不会”。
- **AC-3**：标记“不会”后，该词进入生词本并在所有相关页面实例显示红色强提示（同页首次含行内中文）。
- **AC-4**：标记“会”（或生词本“已掌握”）后，红色提示消失、生词本条目消失；该词仍可悬停查询、可再次标记“不会”。
- **AC-5**：查询词典内、测评包外的词不写入 AssessmentEvidence。
- **AC-6**：查询词典内、测评包外的词不改变词汇量估计（估计前后数值不变）。
- **AC-7**：灰线数量必须是稀疏候选，而不是所有未测命中词。候选生成（C 已对齐）＝**仅 `effectiveFrequencyRank`（frq 优先、bnc fallback）+ 用户显式状态过滤（排除 known/learning），不含 Evidence/band**；算法＝**频率下界阈值**。**首轮阈值 T₀＝有效频率 rank 升序列表的中间索引阈值（index ⌊n/2⌋，0-based）**——完全确定、无未定义参数，任何代理同一输入得同一 T₀；light 候选判定方向与边界（用户确认）：**`effectiveFrequencyRank > T₀`（严格大于，等于不提示）**；随后用 dogfood 密度数据校准分位点。验收方式＝dogfood 记录每百词灰线密度作为参考数据 + 复用「不必要提示」人工验收；不预设固定密度数字。**frq/bnc 双缺失＝hint-ineligible 但 queryable（query eligibility 与 hint eligibility 独立）**。候选不落盘、不改写用户状态、不恢复冻结项。
- **AC-8**：tooltip 不与目标词矩形重叠；上下翻转正确（上方空间不足时显示在下方）；不超出左右视口；不侵入可识别的 sticky/header 安全区域；滚动后定位仍正确。
- **AC-9**：真实 mouse down/move/up 拖选路径可验收：选区产生 → 浮动按钮出现且不被同一手势后续 click 隐藏 → 点击写入 learning。
- **AC-10**：lookup unresolved 不能表现为插件毫无反应——用户对该词的查询尝试至少得到明确的“当前词典未收录”响应（B 已决议：仅提示，不提供加入生词本动作）。**针对的核心入口：悬停查询、点击反馈（含灰线词与无灰线词两类可交互词）**。**不针对的辅助入口：拖选加词**——拖选未收录词维持「无法唯一解析 → 静默不弹」的既有规则，不弹未收录提示、不提供加词按钮（与 B「未收录不进生词本」一致）。**lookup-unresolved 本身不属于灰线（light hint）或红线（strong hint）状态**：未收录词不会因此显示灰线或红线，仅在有查询尝试时给出未收录提示。

## 13. MIGRATION_AND_BACKWARD_COMPATIBILITY

本规格不设计新的 schema/migration。**OPEN_DECISIONS F 已决定：在 E 生效范围内沿用现有字符串键、不升级 schema**（见 §14 F、§4）；本节约束仅列出需要后续设计确认的兼容问题（现有 schema 3 迁移与已批准规则保持不变）：

- **查询词典来源/版本变化**：若查询词典与测评包分离为不同资产，需要定义查询词典的版本标识与兼容规则；是否写入 snapshot 未确认。

## 14. OPEN_DECISIONS

以下六项已由用户于 2026-08-06 逐项决议，并在 2026-08-07 发现与对齐阶段完成 E 验证、D 原型、C 输入/算法/bootstrap 对齐，经第二道 DOCUMENT 审查 `PASS` 与用户最终批准。选项列表保留作为决策依据；每项标注**最终决议与当前状态**。已批准/已决议 ≠ 已实现；不得把批准状态伪装成已经实现或已经获得开发授权。

- **A. “普通英文词原则上可查询”的正式覆盖验收 —— 已决议（2026-08-06）**
  - 选项 1：使用公开语料（如 BN-L 的抽样或公认词频表）定义覆盖，验收 token 覆盖或 type 覆盖的阈值（token 覆盖更贴近阅读体验，type 覆盖更贴近词典完备性）。
  - 选项 2：不设语料阈值，按「常见英文正文中高频 N 个词形」的经验标准人工验收覆盖缺失（RULES dogfood 已定义「覆盖缺失」人工记录）。
  - 选项 3：先不做量化验收，把「可查询」限定为「查询词典命中即交互、未命中给明确响应」，覆盖质量留待 dogfood。
  - 影响：选项 1 最严格但成本最高；选项 2 与现有 dogfood 记录兼容；选项 3 最快但不解决「普通词查不到」的用户体验缺口。
  - **决议：选项 3**（dogfood 驱动覆盖验收：词典命中即交互、未命中给明确「未收录」响应（叠加 B）；覆盖质量用 dogfood「覆盖缺失」人工数字驱动后续扩容决策；不预设词典条目数）。

- **B. lookup unresolved 的最终产品行为 —— 已决议（2026-08-06）**
  - 选项 1：悬停/点击未收录词显示固定文案「当前词典未收录」+ 提供「加入生词本」入口（无释义，仅词形）。
  - 选项 2：只显示「当前词典未收录」提示，不允许无释义的 surface form 直接进生词本。
  - 选项 3：仅提示「未收录」，不提供任何动作（比现状多一个明确响应即可）。
  - 影响：选项 1 让用户能记录生词但生词本出现无释义条目（需定义展示与“已掌握”行为）；选项 2 保持生词本元数据完整；选项 3 最小改动。
  - 身份键无法确定时如何处理（是否允许“裸 surface key”状态、是否需要 schema）是选项 1 的附加问题，属于 OPEN_DECISIONS F 的输入；**F 已决议不升级 schema、不允许裸身份键进入存储**，因此该附加问题随之关闭。
  - **决议：选项 2**（仅提示「当前词典未收录」，不进生词本；生词本始终只含可展示完整元数据的词条；AC-10 入口界定见 §9）。

- **C. 灰线“稀疏”的量化验收与候选生成 —— 已决议并完成输入/算法/bootstrap 对齐（2026-08-06 决议；2026-08-07 对齐）**
  - 选项 1：每屏灰线数量上限（如整页可见区域 ≤ N 个）。
  - 选项 2：每百词密度上限（如 ≤ 5%）。
  - 选项 3：先不定数字，按「不必要提示」dogfood 数字人工验收误提示，反推候选策略。
  - 影响：固定数字验收清晰但可能不匹配真实页面分布；dogfood 数字更真实但验收滞后。
  - 候选召回（该提示的没提示）与误提示（不该提示的提示了）需要人工验收（复用 RULES dogfood 三数字）。
  - **决议（验收方式）：选项 3 + 密度参考数据**（dogfood 期间记录每百词灰线密度作为参考数据，数据积累后再定固定阈值；复用「不必要提示」人工数字验收误提示）。
  - **对齐（候选输入/算法，2026-08-07 用户确认）**：输入＝查询词典频率（frq/bnc）+ 用户显式状态过滤（排除 known/learning），**不含 Evidence/band**；算法＝**频率下界阈值**（阈值数字不写死，作为参数由 dogfood 校准）。候选不落盘、不改写用户状态。
  - **首轮 bootstrap（2026-08-07 用户确认：中间索引阈值公式，无未定义参数）**：首轮灰线阈值**不由任何代理猜数字、也不由人工指定初始 rank**。**确定性公式 f(S) = S[⌊n/2⌋]**：S 为有效 effectiveFrequencyRank 升序列表，n = |S|，取 index = ⌊n/2⌋（0-based）处的值作为首轮阈值 T₀——**偶数 n 时取两个中间元素中的上侧元素**。任何代理对同一查询词典输入得到同一 T₀（同一排序键、同一取整规则，无 N/百分位/默认值待定）。随后用 dogfood 密度数据校准该分位点（校准是后续调整，首轮 T₀ 完全确定）。**light 候选判定方向与边界（2026-08-07 用户确认）：`effectiveFrequencyRank > T₀`（严格大于；等于 T₀ 不提示）**；frq/bnc 均无效时 hint-ineligible 但仍 queryable。「首轮公式生成 → dogfood 数据校准 → 调整」的验收 seam 见 AC-7 与 §10 TEST SEAMS。
  - **不恢复冻结项**：本决议不恢复高置信自动隐藏、Pool B、概率画像或复杂回填。

- **D. 无视觉词的技术交互路线 —— 已决议并完成可丢弃原型（2026-08-06 决议；2026-08-07 原型）**
  - 选项 1：全量无视觉包装（所有可查询词都有包装，无提示词用透明/无样式包装）——命中准确、交互直接，但 DOM 增长需重测。
  - 选项 2：pointer/caret 动态定位（caretRangeFromPoint / caretPositionFromPoint）——不依赖全量 span，但缩放、transform、连字、Shadow DOM、iframe、标点边界与文本节点定位的准确性成本最高。
  - 选项 3：选区/快捷键辅助入口为主——DOM 压力低，但满足不了“放上去即可显示”。
  - 本 Spec 只列约束与决策标准（命中准确、交互可达、DOM/CLS 可测、隐私本地、兼容常见页面）；**原型阶段此前只用于比较路线，不选择实现；经第二道门批准后路线已确定（见下）**。
  - **决议：以一次性可丢弃原型验证选项 1 与选项 2 的 DOM/准确性取舍**（原型必须可丢弃，不演变为生产实现）。**原型已完成（2026-08-07，`work/prototypes/2026-08-07-no-visual-interaction/`）**：路线 1（透明 span + 事件委托）10/10 命中、DOM +3,888、初始扫描 4 ms、CLS 0；路线 2（pointer/caret）8/10——开放 Shadow DOM 失败、长文滚动后误命中相邻词。**已批准生产实施路线（2026-08-07，第二道 DOCUMENT 审查 `PASS` + 用户最终批准）：路线 1＝「透明 span 包装 + 事件委托」（针对开放 Shadow DOM 与同源 iframe 明确处理）；caret 不作为唯一交互基础。** 该批准只确认路线；prototype 是设计证据，不得直接复制为生产实现——真实长文 DOM/CSS/性能须按 R-PERF-1 在实施阶段正式重测，原型性能数字不构成生产 SLA；本 Spec 不规定路线 1 内部未经确认的低层实现细节。选项 3 因与已确认的悬停核心路径冲突而排除。

- **E. 查询词典来源、许可证、规模和更新策略 —— 条件决议（2026-08-06），已验证通过（2026-08-07）**
  - 选项 1：继续使用 ECDICT 全量词典（本地），单独验证许可证与规模，与测评包分离。
  - 选项 2：其他可本地再分发的开源词表（需逐条验证再分发权利链）。
  - 选项 3：维持现状 1,000 core + forms，不扩容，仅补未收录响应。
  - 影响：决定查询覆盖、包体、加载时间与 DOM 上限；许可证未验证前不得公开发布。
  - **决议：选项 1（条件决议）**：查询词典方向为 ECDICT 全量本地词典，与测评包分离。**验证结果（2026-08-07，证据见 `work/research/2026-08-07-ecdict-license-data-feasibility.md`）：E_VALIDATED（限定范围）**。
    - **验证成立的范围**：个人本地 dogfood + 本地打包（load unpacked）、不公开发布——ECDICT 仓库 LICENSE 为 MIT，正面授权 use/copy/distribute；数据可行性实测（原始 CSV 770,611 行 / 65.9 MB；**query-eligible 词 121,340 条**（只依赖身份+展示元数据，不要求频率），其中含有效 frq/bnc 40,090 条、无有效频率 81,250 条；裁剪后按 121 B/词条估算约 14.7 MB，最终以实施口径实测为准）。**该范围内 ECDICT lemma 字符串键身份与 F 决议生效（§5、§13）。**
    - **明确不在验证范围**：对外公开再分发（Chrome Web Store 发布、分享 crx、随公开仓库分发）——中文释义与 BNC 派生数据逐条权利链 UNKNOWN，**未获通过，维持 UNKNOWN**；若未来需要公开，必须 STOP 并将 E/F 返回用户重新决策（fail-closed），任何代理不得自行改用其他词典或静默改变身份模型。
  - 条目数由数据可行性决定、不预设数字；许可证未验证前仅用于个人 dogfood，不公开发布。

- **F. 包外 wordKey 的合法性、版本和未来兼容语义是否需要 schema 变化 —— 条件决议（2026-08-06），已随 E 生效（2026-08-07）**
  - 选项 1：不需要 schema 变化——包外词使用与包内相同的字符串 wordKey 键，仅约束“无 Evidence、不进估计”，迁移语义不变。
  - 选项 2：需要显式命名空间/来源字段——区分词来自查询词典还是测评包，便于未来版本与估计隔离，但需 schema 升级与迁移。
  - 选项 3：暂不允许包外词持有 WordState——保持现状，直到用户确认。
  - 影响：选项 1 最小且与现有 Record 字符串键结构兼容；选项 2 更显式但触碰 schema；选项 3 不推进产品目标。
  - **决议：选项 1（条件决议，已随 E 验证通过而生效）**：包外词使用与包内相同的字符串身份键，不区分来源、不升级 schema、不做迁移；约束层保证不写 Evidence/不进估计；除非未来出现版本/来源歧义再评估选项 2。**生效范围同 E（个人本地 dogfood、不公开发布）；E 验证失败或需公开再分发时，E 与 F 一起返回用户重新决策（fail-closed，见 §18）。**
