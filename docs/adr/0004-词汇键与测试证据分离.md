# ADR-0004：词汇键与测试证据分离

取代 [ADR-0003](./0003-词典优先的单词级-v0.1.md) 中的状态承载方式。

## 决定一：纯屈折词形共享 core 词汇键（wordKey）

个人词汇状态与测试证据的身份键是 `wordKey`——ECDICT core 主词条的小写形式。纯屈折词形（`went / going / gone`）并入映射目标（`go`）的 `wordKey`；页面词形本身若是合法 core 主词条则优先使用自身（`could` 独立于 `can`）。

为什么改：旧实现（2026-07-27 确认的 surface stateKey 契约）让每个小写页面词形持有独立状态，导致同一个词的屈折变体状态互相分裂——用户在页面上标记 `went` 为“会”，`go / goes / going` 仍是未知；首测测过 `go`，`went` 的提示不变。这与用户对“认识一个词”的直觉冲突，也让估计把同一词的多个变体重复计数。

## 决定二：WordState 与 AssessmentEvidence 分离

每个 `wordKey` 维护两条彼此独立的记录：`WordState`（当前页面提示用的会/不会/未知，最后一次显式动作生效）与 `AssessmentEvidence`（最近一次首测或每日测试的结果，每词只留最新一条）。手动标记只更新 `WordState`；首测/每日作答同时更新两者。估计、“是否已测过”、“最久未测”只读 `AssessmentEvidence`。

为什么不能只用 `WordState.source` 过滤：`WordState` 是“最后一次写入生效”的单槽记录。用户先在首测答对某词（source=initial），随后在页面手动标记为不会（source=manual），该词的测试样本就从估计中彻底消失——manual 覆盖破坏了估计的分母与分子。分离后，手动标记随时改提示，而测试样本永不被手动动作抹掉。

## 决定三：schema 3 是一次不可轻易逆转的数据身份迁移

schema 2→3 同批完成：旧 surface key 状态按 forms 映射并入 `wordKey`（冲突按 updatedAt 新者 → manual → learning 仲裁）；从已持久化的首测计划与作答重建旧 `AssessmentEvidence`（assessedAt=0 表示旧作答时间未知）；清空旧审计标记与审计计划。合并是有损方向的（多个 surface 状态折叠为一条），不提供原地 3→2 降级，因此升级前保留旧快照副本。

## 考虑过的替代

- 保持 surface stateKey 不迁移：保留状态分裂缺陷，估计重复计数，被否决。
- 保存完整测试历史（事件溯源）：V0.1 没有任何消费历史的行为，属过度设计，被否决。
- manual 无条件优先的迁移仲裁：会让一次旧手动标记压过其后更新的测试状态，与“最后一次显式动作生效”不一致，被 updatedAt 优先取代。
