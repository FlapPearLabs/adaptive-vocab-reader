# ADR-0001：以阅读辅助协调器作为最高层测试 seam

当前提案把 V0.1 从正文增量和用户动作到标注决策、状态更新、复习候选与本地模型任务的复杂度集中在“阅读辅助协调器”。DOM、词典、本地存储以及 Ollama/LM Studio 均通过 Adapter 接入，不能把各自的实现细节泄漏给领域核心。该提案须在重新 `/to-spec` 时接受或修订。

选择这一边界，是为了让表达候选、表达义项、个性化、提示强度、降级、缓存和保温抽检可以通过一个稳定的高层 Interface 联合验证；同一套正文 fixture 也能复用于纯领域测试、浏览器 content script、SPA 增量场景以及未来文本来源。协调器输出可观察决策，不要求调用方理解内部规则。

代价是协调器承担了多条业务路径的编排责任。实现时必须保持窄 Interface，将候选识别、个人模型、词典解析、Provider 调度和保留策略放在独立内部模块，避免演变为巨型类。任何绕过协调器直接修改掌握状态或直接从 content script 调用本地模型的路径，都应视为架构违规。
